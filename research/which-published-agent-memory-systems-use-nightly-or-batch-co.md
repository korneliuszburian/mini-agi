## Findings

**Scope note.** No system in the sources uses a literal "nightly cron"; "nightly" is approximated by daily-frequency batch reflection (Generative Agents) and idle-time scheduled consolidation (Letta sleep-time compute). Continuous background consolidation is approximated by per-event incremental ingestion (Zep/Graphiti, Mem0, A-MEM). Claims below cite the primary source in brackets; `[S1]`–`[S7]` map to the Sources section. Every figure is quoted from the source that owns it.

### A. Systems with batch / scheduled consolidation

1. **Generative Agents (Stanford, 2023)** — batch reflection on a salience trigger. Reflections are "generated periodically; in our implementation, we generate reflections when the sum of the importance scores for the latest events perceived by the agents exceeds a threshold (150 in our implementation). In practice, our agents reflected roughly two or three times a day" `[S4]` §4.2. This is daily-batch consolidation of raw observations into higher-level memories; measured effect (technical evaluation, TrueSkill): the no-reflection ablation scored μ=26.88 (σ=0.69), no-reflection-and-no-planning μ=25.64 (σ=0.68), crowdworker baseline μ=22.95, and the no-memory/no-reflection/no-planning architecture μ=21.21; the full architecture vs the no-memory baseline gives Cohen's d=8.16. Conclusion drawn by authors: "each of these components is critical to strong performance" `[S4]` §5. (The full-architecture μ value fell in a section my fetch truncated; ordering and d are quoted.)

2. **MemGPT (2023/24)** — scheduled and event-driven batch operations, not nightly. "Timed events that are run on a regular schedule (allowing MemGPT to run 'unprompted' without user intervention)" `[S1]` §2.4. Consolidation is the queue manager's recursive summarization: on memory pressure (warning at ~70% of context), the agent self-edits working/archival memory; at flush (~100%) it evicts ~50% of the window and "generates a new recursive summary using the existing recursive summary and evicted messages" `[S1]` §2.2. Quality vs its own baseline: DMR accuracy 93.4% (GPT-4 Turbo + MemGPT) vs 35.3% (recursive summarization alone) `[S1]` §3.1.1 Table 2. MemGPT reports no separate consolidation cost figures.

3. **Letta sleep-time compute (2025)** — idle-time batch consolidation, the closest published analogue to "nightly". "Instead of sitting idle between tasks, AI agents can now use their 'sleep' time to process information and form new connections by rewriting their memory state" `[S3]` (product blog). Implementation: two agents; the sleep-time agent owns the memory-edit tools and rewrites the primary agent's in-context memory blocks; memory formation is explicitly contrasted with MemGPT's incremental form: "Sleep-time agents on the other hand can continuously improve their learned context to generate clean, concise, and detailed memories" `[S3]`. Frequency is configurable: "The higher the frequency setting, the more tokens your agent will use" `[S3]`. Measured effect (paper): "sleep-time compute can reduce the amount of test-time compute needed to achieve the same accuracy by ~5x on Stateful GSM-Symbolic and Stateful AIME and ... scaling sleep-time compute we can further increase accuracy by up to 13% on Stateful GSM-Symbolic and 18% on Stateful AIME"; on Multi-Query GSM-Symbolic "we can decrease the average cost per query by 2.5x" `[S2]` abstract.

4. **Zep/Graphiti community refresh** — batch layer on top of continuous ingestion (see B). Because dynamic community extension "gradually diverge[s]" from a full label-propagation run, "periodic community refreshes remain necessary"; the dynamic path exists because it "significantly reduces latency and LLM inference costs" `[S5]` §2.3. So the system's own design rationale is: continuous incremental updates for cost/latency, periodic batch recompute for quality.

### B. Systems with continuous background consolidation

5. **Zep / Graphiti (2025)** — per-message incremental ingestion with background semantic construction. Each episode (message) triggers entity extraction (with prior n=4 messages for context), entity resolution, fact extraction, deduplication, temporal extraction, and LLM-based edge invalidation on contradictions ("Graphiti consistently prioritizes new information") `[S5]` §2.1–2.2. Measured quality/cost vs full-context baseline on LongMemEval (conversations ~115k tokens): accuracy +15.2% (gpt-4o-mini) and +18.5% (gpt-4o); latency 31.3 s → 3.20 s and 28.9 s → 2.58 s ("reducing response times by approximately 90%"); context tokens 115k → 1.6k `[S5]` §4.3.2 Tables 2–3. Caveats the paper itself reports: on DMR, Zep scores 94.8% vs MemGPT's 93.4%, but the full-conversation baseline scored 94.4% (gpt-4-turbo) and 98.0% (gpt-4o-mini), so the DMR gap is within noise; and Zep *declined* on single-session-assistant questions (−17.7% gpt-4o, −9.06% gpt-4o-mini) `[S5]` §4.2, §4.3.2.

6. **Mem0 (2025)** — incremental consolidation at write time plus an async background summarizer. Extraction runs per message pair; the update phase runs an LLM tool call per candidate fact choosing ADD / UPDATE / DELETE / NOOP `[S6]` §2.1. A separate "asynchronous summary generation module that periodically refreshes the conversation summary ... operates independently of the main processing pipeline" `[S6]` §2.1. Measured cost vs full-context on LOCOMO: full-context p95 latency ≈17.1 s (p50 9.87 s); Mem0 p50 0.708 s / p95 1.440 s; graph variant p50 1.091 s / p95 2.590 s `[S6]` §4.4; paper claims "91% lower p95 latency and saves more than 90% token cost" vs full-context `[S6]` abstract. Quality: Mem0^g reaches the highest LLM-judge score among memory systems (J≈68.4 overall); "26% relative improvements in the LLM-as-a-Judge metric over OpenAI" `[S6]` abstract, §4.4. Note: on LOCOMO open-domain questions, Zep beat Mem0 (J 76.60 vs 72.93) — a cross-vendor result, not a batch-vs-continuous one `[S6]` §4.1.3.

7. **A-MEM (2025)** — per-interaction continuous evolution. Each new interaction triggers note construction (LLM keywords/tags/context), top-k link generation, and "memory evolution" that rewrites the contextual representation of existing memories `[S7]` §3.1–3.3. Measured cost: "approximately 1,200 tokens per memory operation, achieving an 85–93% reduction in token usage compared to baseline methods (LoCoMo and MemGPT with 16,900 tokens)"; "each memory operation costing less than $0.0003"; processing "5.4 seconds using GPT-4o-mini and only 1.1 seconds with locally-hosted Llama 3.2 1B" `[S7]` §4.3 (Cost-Efficiency Analysis). Retrieval scales to 1M memories at 3.70 µs with linear storage `[S7]` §4.6 Table 4. Quality (DialSim): F1 3.45 vs LoCoMo 2.55 and MemGPT 1.18 `[S7]` §4.3 Table 2.

### C. Cross-cutting

8. **No published batch-vs-continuous head-to-head.** All measured quality/cost differences above are within-system comparisons against full-context or RAG baselines. None of `[S1]`–`[S7]` reports the same system under both nightly-batch and continuous consolidation. **opinion**: the closest evidence for the trade-off is Zep's own §2.3 design claim that continuous dynamic extension trades graph quality (periodic refresh needed) for latency/LLM cost `[S5]`.

## Verdict

**Established.** Two consolidation regimes exist in published agent-memory systems: (1) batch/scheduled — Generative Agents (threshold-based reflection run ~2–3×/day, `[S4]`), MemGPT (scheduled timed events + pressure-driven recursive summarization, `[S1]`), Letta sleep-time compute (idle-time batch memory rewrite, configurable frequency, `[S2]` `[S3]`); (2) continuous background — Zep/Graphiti (per-message KG ingestion + dynamic community update with periodic batch refresh, `[S5]`), Mem0 (per-pair extraction + async summarizer, `[S6]`), A-MEM (per-interaction note evolution, `[S7]`). Reported differences are real but all within-system: continuous systems report large cost wins vs full-context (Mem0 ~91% p95-latency / >90% token reduction `[S6]`; Zep ~90% latency / 115k→1.6k tokens `[S5]`; A-MEM 85–93% tokens `[S7]`); batch systems report quality/throughput wins vs their own non-consolidating baselines (Generative Agents ablation d=8.16 `[S4]`; Letta ~5× test-time-compute reduction, up to +18% accuracy `[S2]`).

**Uncertain.** (a) No source reports a controlled comparison of nightly-batch vs continuous consolidation on the same system — the batch-vs-continuous question is not directly answered in this literature; the only reasoning is Zep's design note that continuous dynamic updates save cost/latency but degrade community quality until a periodic refresh (`[S5]` §2.3). (b) Cost accounting is incomparable across papers (tokens vs latency vs USD, different benchmarks/models). (c) "Nightly" as such is not used by any source; closest are "~2–3 times a day" (`[S4]`) and configurable idle-time (`[S3]`).

**What would settle it.** A controlled ablation running one system (e.g., Letta or Mem0) under (i) per-event consolidation vs (ii) daily-batch consolidation on a fixed benchmark with identical token/latency metering, scored on a staleness-sensitive benchmark (e.g., LongMemEval knowledge-update/temporal categories) to capture the recall-latency trade-off. That study does not yet exist in the sources I reached. No PDFs were unreadable; all sources were fetched as HTML/text and the figures quoted above were verified in the fetched text (the sole exception is one full-architecture score in `[S4]`'s truncated section, which I did not quote).
