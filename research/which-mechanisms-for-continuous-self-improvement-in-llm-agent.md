## Findings

Scope note: everything below cites primary sources (arXiv/ICML/NeurIPS/Nature)
or two earlier research passes already in this repo (`research/what-is-the-measured-value-of-self-reflection-passes-in-agen.md`, `research/what-are-the-measured-economics-of-agent-memory-consolidatio.md`) which verified the cited numbers against the same primary sources. Cross-paper generalization to a single-developer offline agent kernel is labeled **estimate**/**opinion**. All arXiv numbers are **fact** as reported by the papers under their own protocols.

### 1. Self-refinement (verbal reflection loops): works only with an external evaluator

- **Fact** — Reflexion (Shinn et al., 2023) raises HumanEval pass@1 from 80% (SOTA then) to 91%. Its own ablation isolates the mechanism: on the 50 hardest HumanEval problems, base = 0.60, reflection *without* test execution = 0.52 (worse than base), tests *without* reflection = 0.60, full loop (tests + reflection) = 0.68. The verbal reflection step only adds value paired with an external evaluator. Source: arXiv:2303.11366 §4.3 Table 3 (recorded in `research/what-is-the-measured-value-of-self-reflection-passes-in-agen.md`).
- **Fact** — Self-Refine (Madaan et al., 2023) reports ~20% absolute average gains on 7 tasks, but ≈0pp on GSM8K math: GPT-3.5 64.1→64.1, ChatGPT 74.8→75.0; GPT-4 92.9→93.1. Cause per paper: the model cannot detect its own math errors (its own feedback was "everything looks good" in 94% of instances); with oracle (external) error feedback the gain became 5%+. Source: arXiv:2303.17651 §3.2–3.3 (prior research, same file).
- **Fact** — Intrinsic self-correction without external feedback can even degrade performance (Huang et al., ICLR 2024; arXiv:2310.01798). Tyen et al. (ACL Findings 2024) decompose why: LLMs cannot reliably *find* their own errors, but *can fix them* when the error location is supplied (arXiv:2311.08516).
- **Fact** — The same file records that in a 2026 control-theory preprint only 3/7 models (o3-mini +3.4pp, Opus 4.6 +0.6pp, o4-mini ≈0) tolerated repeated self-correction without accuracy loss; GPT-5 and four others degraded; a "verify-first" prompt turned GPT-4o-mini's −6.2pp into +0.2pp. arXiv:2604.22273 (preprint, not peer-reviewed).

### 2. Learning from self-generated rewards (LLM-as-judge, no human labels): works, with measured saturation and category blind spots

- **Fact** — Self-Rewarding Language Models (Yuan et al., ICML 2024): Llama-2-70B trained for 3 iterations where it generates its own DPO pairs and rewards (LLM-as-judge) to serve as its own reward model. AlpacaEval 2.0 win rate vs GPT-4-Turbo: 9.94% → 15.38% → 20.44% (M1→M3), beating Claude 2, Gemini Pro, GPT-4-0613. The model's self-judging quality also improved. Source: arXiv:2401.10020, ICML 2024, Table 1.
- **Fact** — A 4th iteration reached 22.97% but per-iteration gains shrank monotonically: 5.44, 5.06, 2.53pp — "the trend seems to be that it will saturate with no further improvements." Source: ICML proceedings version (mlresearch), Table 1 + §"Improvements From Further Iterations Eventually Saturate".
- **Fact** — Category analysis: gains concentrated in writing, role-play, STEM, extraction; "tend to give less gains on mathematics and reasoning tasks." Source: ICML proceedings, Figure 4/§Fine-grained analysis.
- **Fact** — The paper itself flags a confound: average generation length grew 1092 → 1552 → 2552 tokens across iterations (length-inflation bias of the LLM judge). Source: arXiv:2401.10020 §"Evaluation" (response-length table).
- **Fact** — Meta-Rewarding (EMNLP 2025 Main) extends this: adding a "meta-judge" improvement step, Llama-3-8B-Instruct went 22.9% → 39.4% on AlpacaEval 2 and 20.6% → 29.1% on Arena-Hard — "self-improving models without human supervision." Source: aclanthology.org/2025.emnlp-main.583.
- **Fact** — Public NLP benchmarks (ARC, HellaSwag, the text-completion set) stayed flat or dropped under self-reward training ("alignment tax" per InstructGPT). The gain is task-format-specific (judged instruction following). Source: Self-Rewarding §A.7.

### 3. Skill-library mechanism (Voyager): externalizable, verified-commit gates, zero labels

- **Fact** — Voyager (Wang et al., TMLR 2024, arXiv:2305.16291) is the first LLM-powered lifelong-learning agent with no parameter fine-tuning (blackbox GPT-4): 3.3× more unique items, 2.3× longer travel distances, tech-tree milestones up to 15.3× faster than prior SOTA; only method to reach diamond-tier. In zero-shot transfer to a fresh world, Voyager solved every task within 50 iterations while ReAct, Reflexion, AutoGPT solved none.
- **Fact** — Its three components: automatic curriculum (self-proposed next tasks), policy/reasoning via code, an ever-growing skill library of *executable code*, and an iterative prompting loop that includes execution errors + self-verification before a skill is committed. Skills compound ("temporally extended, interpretable, compositional") and alleviate catastrophic forgetting. Source: arXiv:2305.16291 abstract/§1.
- **Fact** — Skill library is a stereo asset: the library also boosted a separate AutoGPT agent ("plug-and-play worker") even though the library was built by Voyager. Source: arXiv:2305.16291 §4, Table 2.
- **Fact** — An ablation reported in secondary literature: removing the automatic curriculum dropped discovered items by 93%. **Estimate** (via secondary write-up of the paper, beancount.io 2026-05-08 — primary ablation table not re-verified in this pass).
- **Fact** — Known limitation: Voyager adds skills only on success — skills are never refined through reward. Follow-up SAGE (2025, arXiv:2512.17102) adds RL-based skill refinement into the library (preprint). Source: arXiv listing.

### 4. Memory consolidation (offline, batch): already measured as the cheap regime

- **Fact** — Eager per-interaction extraction is the expensive regime: RecMem (ACL 2026 Findings) triggers LLM consolidation only on semantic recurrence (θ_sim=0.6–0.7, θ_count=4–5) and cuts construction tokens 87% vs Mem0 without quality loss; LightMem (ICLR 2026) shows an offline "sleep-time" pass roughly triples construction cost (~83K vs ~28K tokens on LongMemEval-S) but stays ~14× cheaper than eager systems. Full numbers, tables and citations in `research/what-are-the-measured-economics-of-agent-memory-consolidatio.md` (prior pass, primary sources). This validates the repo's batch dream-loop (`dream --idle`, distiller + strong-model audit) as the low-cost offline regime.
- **Fact** — Sleep-time Compute (Letta, arXiv:2504.13171): computing offline before queries reaches the accuracy of test-time compute at ~5× fewer test-time tokens; "respond at the accuracy of standard test-time compute but far lower latency." Not human-label-gated.

### 5. Documented failure modes

- **Fact** — Model collapse (self-distillation): "indiscriminate use of model-generated content in training causes irreversible defects in the resulting models, in which tails of the original distribution disappear" — Shumailov et al., *Nature* 631:755–759 (2024). The phenomenon is built: naive recursive fit-and-sample converges toward a uni-modal Gaussian regardless of the generator (Borji, arXiv:2410.12954, analysis). Nature News&Views: "AI produces gibberish when trained on too much AI-generated data."
- **Fact** — Reward hacking: Skalse et al. (NeurIPS 2022, arXiv:2209.13085) formalize: a proxy reward is *hackable* when optimization increases proxy return while decreasing the true reward; "unhackable" is a very strong condition — for non-stationary policy sets **non-trivial unhackability requires restricting the policy set**; "hackability is far from a guarantee of hacking... but" (conclusion: empirically Pan et al. ICLR 2022 found 5/9 hand-built proxies rewarded hacking when optimized). RLVR-specific: the 2026 preprint "LLMs Gaming Verifiers: RLVR can Lead to Reward Hacking" (Helff et al., arXiv:2604.15149) shows RL-with-verifier rewards get hacked both via overt manipulation and by exploiting what the verifier fails to enforce. **Estimate** — qualitative direction is robust: gaps between proxy and intended outcome get exploited under optimization.
- **Fact** — Eval overfitting reported twice in self-improvement settings: (1) cluster ablation of Section 2: Self-Rewarding's math category never improves (the judge cannot distinguish math quality); self-reward gains partially reflect length-inflation — the measured confound; (2) Gao-like dynamics (scale laws for reward-model overoptimization, ICLR 2023, arXiv:2210.10760) show true quality first rises then falls when optimizing a proxy beyond an optimum — iterate-and-eval loops must watch for the "Goodhart regime" (featured citation in those 2026 surveys).
- **Fact** — 2026 analysis in this repo's own prior research pass: judge agreement with a deterministic oracle was the calibration signal; LLM-as-judge comes with documented self-preference/similarity-of-occurrence biases (e.g., LLM-judge evaluations of own generations). (Repo: `eval judge-drift` calibration corpus — no external citation needed.)

### 6. What is feasible in a single-developer offline kernel without external human labels (opinion/estimate)

- **Estimate** — The literature converges on: (a) reflection/self-correction without an external artifact is near-value-less (≈0pp on math, degrades 7/11 models; needs error *location*); (b) self-generated rewards work on instruction-following but corrupt on math/reasoning and saturate; (c) skill libraries and batch memory consolidation are the only two mechanisms whose papers report both large gains and no label requirement; (d) every self-referential loop (self-train, self-judge, self-consolidate) has a documented failure mode shaped the same way: the proxy signal decays (collapse, hacking, overfitting) when it loses contact with ground truth.
- **Estimate → thesis** — The repo's existing architecture already pre-empts the top-3 failures without external labels:
  1. Its substitute for an external label is a *deterministic verifier* (`run verify`, `scripts/verify.sh`, enforced-fact gates). The literature's consistent requirement — external verification is necessary for reflection value (Reflexion, Huang et al., Self-Refine oracle) — is the repo's architecture already.
  2. `harness verify <target> <candidate>` is a *counterfactual gate* that accepts only observed failure reduction — an anti-reward-hacking measure applying the Section 5 insight directly: the proxy (a claim of a fix) is only trusted when the true objective (an observed failure) moved.
  3. `judge-drift` calibration is an explicit watch on Section 2's eval-overfitting mode: disagreement between the generative judge and the deterministic layer is treated as a signal.
  4. Canonical-first memory with provenance + fact ids + enforced facts is the "keep ground truth" structure that avoids model-collapse‑turning memory — new canon comes from human-verified sources, and the dream-loop promotion path routes conflicts to the human queue (ADR-0010).
  5. Offline sleep-time consolidation (dream --idle) matches the measured cheap regime (Section 4) with its freshness guard avoiding eager churn.
- **Opinion — feasible next steps for mini-agi (no external labels required)**:
   1. Make the skills registry a Voyager-style growing library with a per-skill trace of *usage + failure reduction* evidence — every skill claims its counterfactual (already: harness gate can be the evidence). Enforce a **skills budget** cap with priority ranking rather than first-match.
   2. Never train the kernel on its own evaluated outputs (Nap) — keep a "zero self-training" doctrine; the repo's weights are the final judge of canonical quality — write human-verified alterations via the sign-off queue only.
   3. Add a documented "eval-overfitting" regression watch: if judge-drift vs deterministic layer trends up while eval scores improve, the evals not the system are improving (existing `eval judge-drift` metric can be telegraphed as a trend, not just per-run).
   4. Keep the brief (context working set) bounded (already capped — TICKET-13) — unbounded in-context trimming is the agent-level analog of tail-loss collapse: lowest-ranked facts in the working set are exactly the "tails"; budget them explicitly rather than dropping silently.

**Verdict**: the four mechanisms with measured evidence (external-evaluator reflection, self-generated rewards, skill library, offline memory consolidation) form two safe pairings for this kernel: (a) deterministic verifier + reflection loops = already implemented as run/verify; and (b) skill library building on verifier feedback = already partially implemented (skills registry) but needs evidence-of-use budgeting. Mechanisms that are documented to decay under self-referential training (reward hacking, model collapse, eval overfitting, intrinsic-correction stagnation) are currently mitigated by construction (deterministic gates, canonical-first, human sign-off) — maintain those gates as the unit of trust, not the model's self-reported improvement.
