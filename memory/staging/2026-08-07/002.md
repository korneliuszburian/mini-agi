## S-000 (general)

Self-Refine (Madaan et al., arXiv:2303.17651, verified in full text): a single LLM as generator+critic+refiner improved performance ~20% absolute on average across 7 tasks (GPT-3.5/ChatGPT/GPT-4), but the gains are highly uneven: math reasoning gains are essentially zero (GSM8K GPT-3.5 64.1→64.1, ChatGPT 74.8→75.0, GPT-4 92.9→93.1) because the model cannot reliably identify errors (ChatGPT's feedback is 'everything looks good' on 94% of instances); gains appear (5%+) only when an external source flags incorrectness. Preference/constrained tasks gained 20-49 pp (Dialogue Response GPT-4 25.4→74.6; Constrained Generation 15.0→45.0). Iteration curves show diminishing returns (Constrained Generation 29.0→40.3→46.7→49.7). Feedback quality matters (specific 43.2 vs generic 31.2 vs none 0 on Sentiment Reversal). Of self-refine failures: 61% from feedback suggesting an inappropriate fix, 33% from wrong error location, 6% from refiner misapplying good feedback.

## S-001 (general)

'Two Calls Beat Five Agents' (Prajapati & Mohite, arXiv:2607.26922, verified in full text): structured JSON inter-role communication degrades small-model multi-agent pipelines — Parishad five-role pipeline on Qwen2.5-7B-Instruct dropped GSM8K from 75.0% (direct) to 45.0% and HumanEval from 96.3% to 56.0%; a 7B model produces malformed JSON 30-40% of the time under a complex system prompt, and the parse-failure fallback (pass raw text downstream) causes error accumulation. Switching only the communication format to plain text (no architecture/model change) restored GSM8K to 82.0% and HumanEval to 81.7% (+37 points). On repair: two-call self-refinement beat the pipeline on math (86.2% at 7.4x fewer tokens) but the same ungated implementation destroyed HumanEval (Call-1 95.1% → 66.5%, fixing 4 and breaking 51) because the forced-rewrite Call-2 prompt rewrites working code; a task-aware gate (skip Call-2 on complete code blocks; conservative 'respond CORRECT if no bug') restored 95.1% (skips 163/164). Ablation: no-gate + non-coercive prompt = 96.3% (better than gated); gate + force-rewrite = 94.5% — the forced-rewrite instruction, not the gate, caused the regression. Authors' deployment rule: start from direct prompts; add self-refinement only when direct accuracy <85%; never use structured JSON communication in multi-step pipelines for sub-10B models.

## S-002 (general)

'LLMs Cannot Self-Correct Reasoning Yet' (Huang et al., ICLR 2024, arXiv:2310.01798, Tables 2-4): intrinsic self-correction (no external signal) consistently degraded accuracy while multiplying cost (1→3→5 calls): GPT-3.5 GSM8K 75.9→75.1→74.7, CommonSenseQA 75.8→38.1→41.8; GPT-4 GSM8K 95.5→91.5→89.0; Llama-2 GSM8K 62.0→43.5→36.5. With oracle labels (external signal) the same loop gains (GPT-3.5 GSM8K 75.9→84.3, GPT-4 95.5→97.5). Multi-agent debate at equal inference cost is worse than self-consistency (debate 9 responses 83.0 vs self-consistency 9 responses 88.2 on GSM8K). Prompt-design artifact: on CommonGen-Hard, Self-Refine's apparent gain (44.0→67.0) disappears with a strong initial prompt (plain prompting reaches 81.8, applying self-correction drops it to 75.1).

## S-003 (general)

'Is Self-Repair a Silver Bullet for Code Generation?' (Olausson et al., ICLR 2024, arXiv:2306.09896): cost-aware repair gains are modest at equal budget and sometimes negative — GPT-3.5 on HumanEval ≤ +3%, Code Llama on HumanEval ≤ +10%, GPT-4 on APPS ≤ +8% over i.i.d. sampling at the same sample budget. Sample-budget allocation matters: on APPS, GPT-4 with 10 diverse initial samples + 1 repair each = 1.05x pass@20, but 2 initial + 10 repairs each = 0.97x vs pass@22 — over-investing in repair loses to plain resampling. Repair is bottlenecked by feedback quality: human feedback vs GPT-4's own raised repaired-program pass rate from 33.3% to 52.6% (1.58x); GPT-4 feedback judged inaccurate in 32/80 cases vs 7/80 for humans.

## S-004 (general)

Self-Debugging (Chen et al., arXiv:2304.05128, abstract-level; full text unverifiable): generate→execute→feedback→repair is effective when feedback is a deterministic execution signal (rubber-duck debugging: model inspects own execution results and explains its code). Per the paper's abstract: on Spider +2-3% overall and +9% on the hardest problem level; on TransCoder and MBPP (unit tests available) up to +12%; reusing failed predictions with feedback can match or outperform baselines that generate more than 10x candidate programs (~10x sample-efficiency). It matches the condition separating productive from counterproductive repair: a reliable external verifier (execution/tests, oracle labels, stronger or human feedback).

## S-005 (general)

Schema Reinforcement Learning (SRL; Lu et al., arXiv:2502.18878) is the training-based 'repair' that moves the validator into training via RL with a fine-grained schema-validator reward, improving native valid-JSON generation without decoding-time constraints: Llama-3.1-8B 36.45% → 79.67% (SRL) vs 60.59% (SFT); Llama-3.2-3B 28.51% → 72.50% (SRL) vs 56.48% (SFT); paper claims up to 16% improvement in valid complex JSON generation vs supervised baselines. Generalizes to tool calling: BFCL-Live overall for Llama-3.1-8B 24.08% → 70.10% (vs 52.69% SFT). Ablation (Llama-3.2-3B complex subset): outcome-reward RL 28.51→31.15%; +Thought-of-Structure reasoning →44.89%; +fine-grained schema validator →35.59%. It is the only measured route that improves the native rate (what retries resample from). Trade-off noted by authors: SFT without collected JSON data degrades reasoning, whereas SRL preserves it.

## S-006 (general)

'The Extrapolation Cliff in On-Policy Distillation of Near-Deterministic Structured Outputs' (Li et al., NTU, arXiv:2605.08737, verified in full text): on-policy distillation with reward extrapolation (λ>1) silently collapses the structured-output contract above a closed-form threshold λ*(p,b,c) (teacher modal probability, warm-start mass, IS-clip strength). Measured on Amazon Fashion K=8 listwise-JSON (Qwen3 1.7B→4B): parse rate 94.8% at λ=1.15 → 65.1% at λ=1.25 → 8.5% at λ=1.50; cliff localizes inside the predicted [1.18,1.28] bracket (5-seed CI [1.204,1.228]). NDCG@1 on parsed outputs is statistically flat across the sweep (p=0.61) — the λ effect is concentrated in format-adherence, not ranking quality. Operating just below λ* lifts a 1.7B student to 94.8% parse / useful=0.86, matching an 8B-SFT baseline at one-fifth the parameters. Decoder constraints add only +0.009 parse over unconstrained ListOPD's 0.943. Training-side and decoder-side fixes are complementary; parse-only evaluation can hide the collapse because semantic quality stays flat while the contract breaks.

## S-007 (general)

AgentTether (Zhao et al., Microsoft Research, arXiv:2607.06273, verified in full text): graph-localized diagnosis + behavior-scoped guidance + repair memory beats other repair patterns for failed multi-step tool-use runs. Measured on 261 τ-bench tasks (Qwen3.7-max), ≤3-iteration repair budget: overall (n=123) Blind-retry 43.09% → Outcome-feedback 39.02% (worse than blind retry) → Reflexion 44.72% (+1.63) → AgentTether-post-run 60.16% (+17.07) → AgentTether 69.11% (+26.02); on hardest Banking domain (n=83) blind 26.51% → AgentTether 59.04% (+32.53 pp); guarded run-time intervention adds +12.05 pp over post-run-only. Root cause precedes symptom by a median of 4 required steps (up to 26), upstream in 79% of runs; one root error cascades into 3.2 further violated checks; one-shot diagnosis adherence decays below 50% by step 13 (step 8 on Banking) — diagnosis must be carried and re-applied at run-time. AgentTether reduces agent turns (66.5→56.4) and end-to-end tokens (1,376K→1,197K) — repair is cheaper than re-executing. Outcome feedback alone can be counterproductive in policy-constrained domains.

## S-008 (general)

'Reinforced Agent' (Ta, Zhu, Shayandeh, Apple, arXiv:2604.27233, verified in full text): a separate reviewer agent evaluating provisional tool calls before execution (progressive-feedback loop plus best-of-N variants), base GPT-4o, on BFCL and τ²-bench. Helpfulness–Harmfulness decomposition: o3-mini corrects 36.8% of errors while breaking 11.7% of correct cases (3.1:1 benefit-to-risk) vs GPT-4o 34.9%/12.9% (2.7:1) — a good reviewer still breaks ~12% of correct tool calls. Net effects: BFCL irrelevance detection 84.9→90.4% (+5.5%), τ²-bench average 48.7→55.8% (+7.1%); progressive feedback beats best-of-N (+3-8%). τ² failure-mix shift: policy-constraint violations −13%, missing context-awareness −9%, but over-verbalization +17%. Latency is the binding constraint: 6.2x on single-turn BFCL (1.27→7.87 s) but only 2.4x on multi-turn τ² (amortized over ~40 turns) — a reviewer loop is ROI-positive only where errors are costly and latency amortizes. Requires a reasoning reviewer and always pays a ~12% harmfulness tax that a deterministic verifier does not.

## S-009 (general)

VeriHarness (Ray & Goyal, arXiv:2607.14167, verified in full text): feedback content determines repair success in a generate-validate-retry loop (50 paired TextWorld games, four-call cap). Feedback carrying failure location, observed value, and admissible alternatives raised terminal success from 14/50 to 36/50 for Qwen2.5-Coder-14B (+44 pp, CI 28-60, p=3.15e-5) and 8/50 to 29/50 for Llama-3.1-8B (+42 pp). Ablation: prose with same repair values gains the same +42 pp; TypedFields (keyed JSON record + label) differs from matched prose by only +2 pp (Qwen)/0 (Llama), p=1.0 both — 'no evidence that JSON syntax itself improves repair'; admissible alternatives account for most of the gain (+36/+40 pp) since LocObs (location+value, no alternatives) stays at baseline. Extra calls only help when the retry receives new information; raw-diagnostic retries are flat from 4 to 8 calls while structured feedback keeps gaining. Typed feedback uses fewer calls and 14%/10% fewer prompt words.

## S-010 (general)

MERIT (Vo et al., MBZUAI/HCMUT, arXiv:2608.05906, verified in full text): cross-query repair memory (retaining oracle-verified corrections as positive memory and unsuccessful directions as negative, with a deterministic error-type classifier and hybrid dense+BM25 retriever) improves repair over stateless iterative repair on Text-to-SQL: Spider 66.34→69.79 (paired Δ+3.45 pp, 95% CI [+1.97,+4.96]); BIRD 47.35→48.44 (Δ+1.09 pp, weaker evidence). But MERIT is NOT reliably better than untyped dynamic retrieval (tie on Spider, +0.28 pp on BIRD) — the added structure is worth ≈0; Reflexion-style verbal memory beats MERIT on BIRD (51.24 vs 48.44, Δ−2.80, CI [−4.15,−1.46]) at ~2.4x token cost. Negative memory contributes little (−0.13/−0.09 pp); schema-local experience is the most consistent benefit (cross-database-only retrieval costs −0.93 pp Spider, −2.74 pp BIRD). Memory does not reduce total tokens vs stateless (Spider 5.27M vs 2.53M, BIRD 17.6M vs 9.3M).

## S-011 (general)

Parse-then-repair loops reach ~100% within scope: (1) FEniCS natural-language interface (Upadhyay & Reinhart, arXiv:2606.10928): 9/15 valid on first pass (60%), all remaining repaired after retry → 100.0% final valid parse rate, 100.0% problem-class and 97.1% field-extraction accuracy; one unrecovered invalid-geometry failure in a separate 10-case benchmark (90% final). (2) PCN-Rec (Dixit & Dixit, arXiv:2601.09771): verifier-accepts-only certificates with deterministic constrained-greedy repair raise constraint pass rate to 98.55% (feasible users, n=551) vs a one-shot no-verification baseline, at a 0.021 absolute NDCG@10 cost. Deterministic verifier + scoped repair closes most of the residual gap (to 98-100%) without closing the semantic-value gap.

## S-012 (general)

LLM-as-judge reliability limits: (1) Merge-conflict resolution judge (Shen, arXiv:2607.27674, Tables 1-4): an LLM judge calibrated against human labels (n=292) reached 100% precision (zero false accepts) at 64.6% recall (accuracy 78.1%), and the LLM judge accepted 4 of 5 resolutions that fail the deterministic structural check — 'structural correctness must not be delegated to an LLM'. The same study's solver (deterministic gates: parses, no leftover markers, no duplicate declarations; up to 4 retries feeding validator errors back) reaches 95.8% structural validity on true conflicts. (2) Counsel (Pisupati et al., arXiv:2606.21627, verified in full text): process-level LLM-judge critiques on τ-bench/DA-Code, human meta-evaluated (Krippendorff α≈0.78, 1,131 annotations); strongest judge ~88% agreement on error location but only ~65% on reasoning quality; best judge's critiques are 'spot on' only 58-63% of the time on τ-bench retail (Qwen3 63%, GPT-OSS-120B:high 58%) and 43-60% on DA-Code. When repair feedback is LLM-generated, the judge's own reliability caps the repair ceiling.

## S-013 (general)

AgentDebugX (Zhu et al., UIUC/Toronto/Google/Stanford, arXiv:2607.18754, verified in full text): supplying the error location is the dominant lever for repair reliability — confirms the Tyen et al. principle ('LLMs cannot find reasoning errors, but can correct them given the error location'). Multi-turn root-cause agent DeepDebug (structure-guided reading, cross-examination, auditable report with responsible agent+step, evidence, one concrete fix; read-only over the trace): on Who&When (n=184) 56.0% responsible-agent accuracy vs 47.8% for best single-pass; strict agent-and-exact-step 28.8% vs 21.7%. On end-to-end recovery (GAIA validation, 165 tasks): localized fix repairs 13/73 failed tasks in one rerun vs 4/73 (CRITIC), 5/73 (AutoManual), 6/73 (Reflexion); overall 55.8→63.6% (+7.9 pp), largest gain on Level-2 multi-hop (48.8→61.6). Cost: ~5 model calls / 12.8K tokens vs 8.1K for one whole-trace pass (1.6x). Caveats: gain is model-dependent (a single global reading can be stronger on hosted backbones — motivating per-model routing), and swapping the structure-aware reading for a second global searcher costs 4.8 strict points on gpt-5.4-mini. Single toolkit, no third-party replication yet.

## S-014 (general)

'Evidence Lock Before Commitment' (Singh, arXiv:2608.05353, verified in full text): the judge's interface matters — freezing a judge's extracted evidence as the exclusive input to the verdict call hurts. Across 24,000 judgments (1,500 comparisons x 4 protocols x 2 answer orders x 2 judges — Claude Sonnet 4.5, GPT-5; HelpSteer3/FeedbackQA/CoVal): evidence-locking reduces preference agreement by 4.3 pp (Claude)/5.6 pp (GPT-5) vs structured one-call judging (71.7/70.0% vs 76.0/75.6%) and increases answer-order inconsistency by 9.5/8.0 points; pointwise locking is worse (67.3/69.2%); structured one-call evidence elicitation stays close to standard judging (75.3-76.0%) — the harm is the frozen, exclusive record, not asking for evidence. Locked judging costs far more (mean completion tokens 1,279 → 4,183 evidence-lock → 6,825 pointwise). Removing source access degrades the downstream decision by 4-6 pp and doubles order sensitivity — auditability should be additive (record + source), not a frozen replacement.

## S-015 (general)

GGC (Yang et al., NTU/A*STAR, arXiv:2607.28082, verified in full text): when-to-repair is a measured design lever — selective correction beats correct-all. On Text-to-SPARQL (MCQA, 31,570-test; fine-tuned Llama-3.2-3B): of 3,085 generated-query errors, 77.70% are semantic (executable-but-wrong) vs only 21.07% syntax errors — execution-based correction triggers (common retry-on-error pattern) miss ~78% of true failures. A binary risk classifier gate (RoBERTa): accuracy 98.95%, recall 92.11%, FPR 0.31%, triggering the corrector on only 9.31% of queries. End-to-end: Generator-only 90.23% → correct-all (Gen+Corr) 92.34% → selective (Gen+Gate+Corr) 98.33% query accuracy, with ~45% less inference time than correct-all — correcting everything costs 2x and lands 6 pp below selective correction because unnecessary rewriting corrupts originally-correct queries. Threshold-robust (τ 0.25-0.75). KG-execution feedback adds little (98.27→98.70).

## S-016 (general)

'The I Don't Know Filter' (Broecker et al., UC Davis/Okareo, arXiv:2607.04034, verified in full text): abstention via a consistency-based filter is the cheapest repair (no second generation). Introduces IDKS = (C−I)/N (correct minus incorrect calls over total, abstentions neutral, −1..1), penalizing confident-but-wrong calls. Filter: run the agent K times (K=2..5), feed cross-run feature dispersion into a trained random forest, replace outputs above a threshold with 'I don't know'. Measured on three 3B-class SLMs (Llama-3.2-3B, Qwen2.5-3B, Phi-4-mini): IDKS gains often large — APIGen 0.342→0.541, Irrelevance 0.025→0.229, Parallel Multiple 0.320→0.490; whitebox features help most but marginal over gray ('the core uncertainty signal is largely captured at the output and probability levels'); Simple Java is a clear counterexample. Two failure modes: (1) confident incorrectness — low variance read as reliability (int-list call repeated on all five repeats, no signal to intervene, needs external type verification); (2) superficial formatting inconsistency — semantically-identical calls differing in surface form filtered as uncertain (remedy: canonicalize before feature extraction). Baseline IDKS declines as K rises, yet filter gains grow with K. Abstention gates must be paired with content-level checks, not variance alone.

## S-017 (general)

'The Tell-Tale Trace' (Sourav & Balwani, arXiv:2608.03291, verified in full text): generic retry reproduces the failure mode while procedure-directed repair rescues it, measured on solver-certified SAT/UNSAT CNF reasoning. SAT failures show 'premature verification collapse' (wrong traces half as long, more verification-heavy and cyclic, lower-entropy, finalizing earlier 77.1% vs 89.8%, clause coverage unchanged). UNSAT failures substitute assignment search for contradiction proof. Early-warning is model-dependent (80.2% of Llama3-8B wrong traces flagged early, only 35.7% for Llama3-70B). The decisive repair result (Table 2, Llama3-70B, 52 wrong-SAT completions): generic retry ('try again carefully', no strategy) → 10.0% accuracy (correcting 6/52, 11.5%); targeted proof-search prompt → 85.0% accuracy (correcting 44/52, 84.6%) — paired +73.1 pp, McNemar-significant. This is the controlled measurement that 'retry harder' and 'retry smarter' are different mechanisms — the identical model on identical instances goes from 11.5% to 84.6% corrected solely by replacing a strategy-free retry with a procedure-directed one. Caveats: post-hoc and oracle-assisted, generic-retry baseline unmatched in prompt length, and early-warning 'is not a general failure detector'.

## S-018 (general)

'Amplitude-Only FFN Intervention for Tool-Structured LLM Inference' (Xu et al., arXiv:2607.11183, abstract-level — PDF only, no HTML): inference-time FFN intervention as a repair route needing no retraining; a previous direction-changing intervention (Orthogonal Residual Projection) 'produced more regressions than repairs'. Amplitude Gating preserves FFN weight directions, modulates activation magnitudes, with a gated candidate-generation → ranking → acceptance/fallback pipeline and paired Per-Sample Fix-Harm Evaluation (PFHE). Exploratory offline mixed selector raises Qwen3.5-9B tool-route micro-average 38.66% → 42.92% (+4.27 pp); two Hermes function-call endpoints improve +7.64 and +7.62 points. PFHE view over 2,556 units: 48 fixes vs 26 harms (≈1.85:1 fix:harm), 294 preserved-correct, 2,188 preserved-wrong — even a successful intervention harms ~1 case for every ~2 it fixes. Authors report negative transfer across models/endpoints ('retain oracle headroom but no positive train-selected fixed tool route'); their conclusion: 'results support model- and task-specific selection with strict fallback, not a universal AG switch'. Numbers come from the abstract text; confidence in fix/harm counts high as stated directly in the abstract.

## S-019 (general)

Synthesis across §5 (repair patterns): repair loops are only reliably productive when an external, trustworthy signal (tests, oracle labels, a stronger model, a human) drives them; purely intrinsic repair reliably degrades correctness. The one measured intrinsic-but-external-verified exception is cross-episode repair memory (MERIT): +3.5 pp (Spider), driven mainly by schema-local episodic experience, at token overhead and without beating untyped retrieval. Correcting everything is worse than correcting selectively (GGC: routing ~9.3% of queries through a corrector reached 98.33% vs 92.34% correct-all at 45% less inference time — unneeded correction is itself a failure source, so a gate deciding when to repair is as important as the repair itself). For structured-JSON output the reliable repair equivalent is the deterministic verifier + retry/regenerate loop.
