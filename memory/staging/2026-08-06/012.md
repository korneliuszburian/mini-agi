# Staged candidates (dream distiller)

## S-000 (general)

MemGPT (paper arXiv:2310.08560 §2.2) separates main context (LLM prompt tokens: system instructions, working context, FIFO queue) from external context (archival storage, a read/write database of arbitrary-length text objects; and recall storage, the message database); messages evicted from the FIFO queue are stored indefinitely in recall storage and remain readable via MemGPT function calls.

## S-001 (general)

MemGPT (arXiv:2310.08560 §2.2) queue manager enforces a warning token count (e.g. 70% of context window) that inserts a system 'memory pressure' warning so the LLM can move data to working context or archival storage, and a flush token count (e.g. 100%) at which it evicts a count of messages (e.g. 50% of context window) and generates a new recursive summary from the existing recursive summary plus evicted messages; the FIFO queue's first slot holds that recursive summary.

## S-002 (general)

MemGPT (arXiv:2310.08560 Table 2) on DMR (500 MSC conversations, gpt-4-turbo) reaches 93.4% LLM-judge accuracy vs 35.3% recursive-summarization baseline, 32.1% raw GPT-4 (92.5% with MemGPT), 38.7% GPT-3.5 Turbo (66.9% with MemGPT).

## S-003 (general)

Letta docs describe 'dreaming' (successor of MemGPT): background subagents review recent conversations, consolidate lessons, and update memory without interrupting active work, runnable after a configured number of user messages or on context-window compaction, plus a /doctor audit for placement, duplication, and system-prompt token usage.

## S-004 (general)

The 70%/100%/50% MemGPT eviction numbers are framed as examples ('e.g.') in the paper, not a tuned optimum; no ablation of eviction fraction was found in reviewed sources.

## S-005 (general)

Generative Agents (arXiv:2304.03442 §4.1) retrieval score = alpha_recency*recency + alpha_importance*importance + alpha_relevance*relevance with all alpha = 1; recency is an exponential decay over sandbox game hours since last retrieval (decay factor 0.995); importance is an LLM-assigned 1-10 integer at creation; every memory object carries creation and most-recent-access timestamps; the memory stream is unbounded and decay only re-ranks at retrieval.

## S-006 (general)

Mem0 memory decay is a soft ranking bias, never a filter — at worst it scales a candidate's score by 0.3x; scaling band 0.3x-1.5x (approx 1.5x just-accessed, 0.3x floor for months-idle); opt-in per project and off by default; widens candidate pool to top_k x 3 (floor 50); reinforcement per memory capped at most recent 20 touches.

## S-007 (general)

Mem0 publishes decay mechanics (scaling band, lifecycle stages) but no measured retrieval-quality number (e.g. recall/accuracy delta with decay on/off); effectiveness is asserted, not benchmarked on that page.

## S-008 (general)

Decay-as-ranking-bias (Mem0) and decay-as-recency-weight (Generative Agents) are the only decay mechanisms found in reviewed sources; neither removes data.

## S-009 (general)

Mem0 default add path is ADD-only extraction: a new fact is stored without silently rewriting an older one; explicit update or delete operations are used to correct or remove a memory.

## S-010 (general)

LangGraph InMemoryStore is a plain dict-backed store with no TTL, eviction, or expiry logic; its docstring says data is lost when the process exits and recommends a database-backed store for persistence; retention policy is delegated to the backing database or application.

## S-011 (general)

Mem0 extraction pipeline: step 1 context lookup (checks related existing memories to avoid storing the same fact again), step 3 deduplication and embedding (redundant facts removed, then each memory embedded).

## S-012 (general)

Mem0 Dream merge folds duplicates into one canonical memory; the folded record is hidden from reads by default (the canonical memory is returned), retained rather than deleted, and surfaced with include_merged=true; runs as memories are added.

## S-013 (general)

Zep (arXiv:2501.13956 §2.2) two-stage dedup during ingestion: entity resolution (embedding cosine + full-text candidates then LLM duplicate check) and edge/fact dedup, where hybrid search for relevant edges is constrained to edges between the same entity pairs as the proposed new edge, significantly reducing dedup computational complexity.

## S-014 (general)

A-MEM (arXiv:2502.12110 §3.3) merges new memories into semantically near existing notes instead of deduplicating by deletion: for each near neighbor the LLM decides whether to update its context, keywords, and tags, and the evolved note replaces the original.

## S-015 (general)

Dedup happens at write time across systems as a way to keep the store from growing with near-identical facts; the dedup rate (how much growth is prevented) is not reported by any reviewed source.

## S-016 (general)

Zep/Graphiti (arXiv:2501.13956 §2.2.3) uses a bi-temporal model: timeline T (when a fact holds) and T' (transactional ingestion), each edge storing t_valid, t_invalid, t'_created, t'_expired; an LLM compares new edges against semantically related existing edges for contradictions and invalidates temporally overlapping affected edges by setting t_invalid to the invalidating edge's t_valid; Graphiti prioritizes new information; retrieval returns the t_valid/t_invalid range so stale-but-historical facts remain representable.

## S-017 (general)

Mem0 Dream supersede marks an older memory as superseded and links it to the newer fact; superseded memories are not deleted and not hidden by default (normal search/get still returns them, badged as superseded); latest_only=true filters them out; runs as memories are added on every plan.

## S-018 (general)

Zep (arXiv:2501.13956 Table 3) time-aware invalidation improves LongMemEval knowledge-update and temporal-reasoning categories vs full-context reading: with gpt-4o, knowledge-update 78.2% to 83.3% and temporal-reasoning 45.1% to 62.4%.

## S-019 (general)

Invalidation/supersede is the near-universal answer to 'outdated fact' in reviewed systems: keep the history, hide or timestamp the old truth, never destroy it.

## S-020 (general)

Mem0 per-memory expiration: an expiration_date (YYYY-MM-DD, UTC, date-inclusive) stops the memory surfacing in search once the date passes; nothing is deleted — search() and get_all() skip it, fetching by ID still returns it, clearing the date restores it; no date means never expires (default); malformed dates fail open.

## S-021 (general)

Mem0 distinguishes three retention policies: Expiration (hides, data kept, reversible), Decay (re-ranks, data kept, never filters), Delete (permanent, irreversible).

## S-022 (general)

Generative Agents (arXiv:2304.03442 §4.2) reflection recursively synthesizes observations into higher-level 'reflections' appended to the memory stream; the stream is compacted in meaning, not in size.

## S-023 (general)

Mem0 Dream synthesis distills memories into higher-order pattern memories written alongside existing memories, never in place of them, gated on at least 20 memories per user and a cadence (7 days Pro, daily Enterprise).

## S-024 (general)

Zep (arXiv:2501.13956 §2.3) community subgraphs are periodic summaries of entity clusters (label propagation, dynamically extended); the paper concedes communities gradually diverge from a complete label propagation run, so periodic community refreshes remain necessary — even the summarization tier requires scheduled re-runs as facts accumulate.

## S-025 (general)

No reviewed source reports a measured compression ratio (bytes or fact-count reduction) for consolidation tiers.

## S-026 (general)

Zep vs MemGPT vs full-context on DMR (500 MSC conversations, gpt-4-turbo): MemGPT 93.4%, Zep 94.8%, full-conversation baseline 94.4%, session-summary baseline 78.6%, recursive summarization 35.3%.

## S-027 (general)

Zep on LongMemEvalS (avg ~115k-token histories, retrieving 10-20 facts/entities per query): 63.8% (gpt-4o-mini) / 71.2% (gpt-4o) vs full-context 55.4% / 60.2%; latency 3.20s / 2.58s vs 31.3s / 28.9s (~90% lower); average context tokens 1.6k vs 115k; accuracy improvements up to 18.5% (gpt-4o), 15.2% for gpt-4o-mini.

## S-028 (general)

Zep paper caveat (arXiv:2501.13956 §4.2): DMR conversations contain only 60 messages each, easily fitting within current LLM context windows, so DMR barely exercises retention.

## S-029 (general)

LongMemEval (arXiv:2410.10813, ICLR 2025): long-context LLMs lose 30-60% accuracy reading the full LongMemEvalS history vs oracle retrieval; GPT-4o 0.870 oracle to 0.606 full-history (30.3% drop).

## S-030 (general)

LongMemEval (arXiv:2410.10813 Fig 3a): commercial memory systems on histories ~10x shorter: ChatGPT (GPT-4o) 0.5773 vs offline reading 0.9184 (37% drop); Coze 0.3299 (64% drop).

## S-031 (general)

LongMemEval design deltas under growth: fact-augmented key expansion improves memory recall@k by 9.4% and QA accuracy by 5.4%; time-aware query expansion improves temporal-reasoning recall by 6.8-11.3%; Chain-of-Note plus structured format improves QA accuracy by up to 10 absolute points.

## S-032 (general)

LongMemEval storage-granularity finding: compressing sessions into individual user facts harms overall performance due to information loss but improves multi-session reasoning accuracy.

## S-033 (general)

A-MEM (arXiv:2502.12110 Table 4) retrieval time grows from 0.31 microseconds (1,000 memories) to 3.70 microseconds (1,000,000 memories) with linear O(N) memory (1.46 MB to 1464.84 MB); per-operation cost about 1,200 tokens vs about 16,900 for MemGPT/LoCoMo baselines (85-93% reduction), measured by the authors on their own system.

## S-034 (general)

No controlled experiment was found isolating any single retention policy (e.g. decay on/off, eviction threshold, supersede vs delete) with retrieval-quality numbers; such numbers are published only for whole systems (Zep, MemGPT) on fixed benchmarks, not for the retention mechanism in isolation.

## S-035 (general)

No reviewed source reports dedup rates, compression ratios, or fact-count growth over time; whether retention actually bounds storage is unanswered in every reviewed source.

## S-036 (general)

Agent memory systems almost universally keep the long-term fact store append-only and unbounded, solving 'growth' by bounding only the in-context tier and by re-ranking/superseding at retrieval: MemGPT/Letta evicts the context queue to a recursive summary while archival/recall storage grows indefinitely; decay exists as a retrieval-time ranking bias and never deletes; dedup is write-time; invalidation/supersede is timestamp-based and non-destructive; per-item expiry exists as soft-hide (Mem0 expiration_date) and is absent from LangGraph's core store.
