## S-000 (general)

RecMem (arXiv:2605.16045, ACL 2026 Findings) frames the core dichotomy in LLM memory consolidation: existing systems invoke LLMs to process every incoming interaction for memory extraction ('eager consolidation'), which leads to substantial token consumption; RecMem's fix triggers LLM consolidation only when semantically similar interactions recur (thresholds theta_sim=0.6-0.7, theta_count=4-5), buffering everything else in an embedding-only 'subconscious' store.

## S-001 (general)

Measured construction-token costs on LoCoMo (GPT-4.1-mini), per conversation: Mem0 1,520.8K / A-Mem 1,459.9K (eager, per-turn) vs RecMem 193.2K (recurrence-based batch) = -87.3% vs Mem0, -86.8% vs A-Mem (RecMem Table 1).

## S-002 (general)

On LoCoMo with GPT-4o-mini, construction tokens: Mem0 1,233.5K / A-Mem 1,143.3K vs RecMem 202.4K, i.e. up to ~7.8x fewer tokens for RecMem (RecMem Table 1).

## S-003 (general)

On LongMemEval-S (500 conversations, ~115K tokens avg), GPT-4.1-mini construction tokens: Mem0 1,626.5K / A-Mem 1,264.3K vs RecMem 365.5K = -77.5% / -71.1% (RecMem Table 2).

## S-004 (general)

RecMem's query-time token cost stays comparable to eager baselines (e.g. LoCoMo GPT-4o-mini: 2.73K vs Mem0 1.99K), so the saving concentrates in construction; the authors argue (opinion, their claim) that these construction-time differences accumulate over time and can dominate total LLM usage in streaming deployments (RecMem §4.2).

## S-005 (general)

LightMem (arXiv:2510.18866, ICLR 2026) total (online+offline) token usage on LongMemEval-S, GPT-4o-mini: A-MEM 1,605.8K / MemoryOS 2,991.8K / Mem0 1,152.6K vs LightMem(r=0.7,th=512) 28.25K = 10x-38x fewer total tokens (GPT), 6.9x-21.8x (Qwen) vs baselines (LightMem Table 2).

## S-006 (general)

LightMem's online-only cost (soft updates, no offline pass) is up to 105.9x (GPT) / 117.1x (Qwen) token reduction and 159.4x / 309.9x fewer API calls vs baselines (LightMem Abstract, §5.2).

## S-007 (general)

Measured cost of an explicit batch consolidation pass: LightMem's offline 'sleep-time' OP-update pass raises construction cost vs online-soft-update alone — e.g. LongMemEval-S GPT-4o-mini LightMem(r=0.7,th=512): online 28.25K tokens / 18.4 calls / 283.8s runtime -> with OP-update 83.44K / 125.5 calls / 496.0s; the batch pass roughly triples construction cost but stays ~14x cheaper than Mem0's eager construction (1,152.6K) (LightMem Table 2).

## S-008 (general)

Mem0 (arXiv:2504.19413) reports >90% token-cost saving and 91% lower p95 latency vs processing the whole 26,031-token conversation each query (Mem0 retrieves ~1,764 tokens avg) (Mem0 Abstract, §1, Table 2).

## S-009 (general)

Mem0 latency on LOCOMO: total p95 = 1.44s (Mem0) / 2.59s (Mem0^g) vs full-context 17.12s; search p95 0.20s vs LangMem 59.82s (Mem0 Table 2, §4.3-4.4).

## S-010 (general)

Zep/Graphiti (arXiv:2501.13956) on LongMemEval-S (~115K-token conversations): response latency 3.20s (gpt-4o-mini) / 2.58s (gpt-4o) vs full-context 31.3s / 28.9s = ~90% latency reduction while avg context drops 115K -> 1.6K tokens (Zep Table 2, §4.3.2).

## S-011 (general)

LightMem runtime (memory-bank construction) speedups over eager baselines: 2.9x-12.4x (GPT), 1.6x-6.3x (Qwen) on LongMemEval-S (LightMem §5.2).

## S-012 (general)

Sleep-time Compute (Letta, arXiv:2504.13171) targets latency by doing inference offline before queries, claiming you can 'respond at the accuracy of standard test-time compute but with far lower latencies'; it reduces test-time tokens needed to reach the same accuracy by ~5x (Stateful GSM-Symbolic, Stateful AIME) (Abstract, §5.1).

## S-013 (general)

RecMem quality: selective batch consolidation matches or beats eager systems on accuracy — best overall among memory-based methods on both benchmarks (LoCoMo GPT-4.1-mini: 81.10 vs Mem0 62.92 / A-Mem 68.83; LongMemEval-S: 76.80 vs 71.20 / 71.60, and beats FullContext 66.20); but on short LoCoMo conversations FullContext still slightly outperforms RecMem (76.43 vs 72.47, gpt-4o-mini), i.e. the consolidation saving is not free on small contexts (RecMem Tables 1-2).

## S-014 (general)

LightMem reports higher ACC and lower cost than all memory baselines (LongMemEval-S GPT-4o-mini: 68.64 vs Mem0 53.61 / A-Mem 62.60 / FullText 56.80), i.e. no measured quality-cost tradeoff in their eval; ablation shows removing topic segmentation costs -6.3% ACC (GPT) (LightMem Table 2, §5.4).

## S-015 (general)

Mem0: full-context still scores highest on LLM-as-Judge (J~72.90%) but at 17s p95; Mem0 scores J=66.88 at 1.44s — the measured accuracy/latency frontier (Mem0 Table 2, §4.3).

## S-016 (general)

Zep: DMR 94.8% vs MemGPT 93.4% (gpt-4-turbo); LongMemEval-S +15.2% (gpt-4o-mini) / +18.5% (gpt-4o) over full-context while cutting latency ~90%; largest gains on temporal-reasoning, multi-session, single-session-preference; caveat: single-session-assistant questions regress (-9.1% / -17.7%) (Zep Abstract, Table 1, Table 3).

## S-017 (general)

MemSIF (arXiv:2608.01742, dual-track write-time 'CoreFact' + query-driven 'ActiveFact' consolidation): on LoCoMo (Qwen3-4B), deferred/query-time consolidation costs more tokens per query (Full 3,052 vs CoreFact-only 1,935 tokens/q) but buys quality, especially on low-salience evidence (LSHU subset 85.69 vs 74.45; total ACC 75.62 vs 67.43); under Qwen3-32B it beats GAM by 5.78 ACC at -40.6% tokens/query (2.41K vs 4.06K) (MemSIF Table 4).

## S-018 (general)

Sleep-time Compute: amortizing one offline pass across ~10 related queries cuts average cost per query 2.5x (modeling test-time tokens at 10x sleep-time token cost); scaling sleep-time compute adds up to +13% (GSM) / +18% (AIME) accuracy; at high test-time budgets pure test-time compute is slightly better (extra pre-computed context distracts); SWE case study shows ~1.5x fewer test-time tokens at low budgets (Abstract, §5.2-5.3, §6).

## S-019 (general)

Auto-Dreamer (arXiv:2605.20616, learned RL-trained offline consolidator): consolidating offline (batch) into a 12x smaller active memory bank improves ScienceWorld by ~7 points over fixed/RL/prompted baselines and generalizes to ALFWorld/WebArena at 6x less memory; quality-only evidence, no token economics reported in abstract.

## S-020 (general)

Complexity model (LightMem §4, estimate — the paper's own accounting, not independent measurement): eager systems are O(N) summarization+update calls per N-turn dialogue; buffered/compressed systems are O(N*r^x*T/th) where r is compression rate, T avg tokens/turn, th buffer capacity — the mechanism behind the 10x-38x token gaps.

## S-021 (general)

Benchmark numbers are not directly comparable across papers (opinion): different eager baselines, backbones (GPT-4o-mini/4.1-mini/Qwen3), datasets (LoCoMo ~16K tokens vs LongMemEval-S ~115K tokens), and evaluation protocols (LLM-as-Judge vs F1) vary; no single published 'per-run extraction vs batch consolidation' cost ratio exists, and the closest measured pairs — RecMem's 193K vs 1,520K (7.8x) and LightMem's 28K vs 1,153K (41x) — are different implementations of the same dichotomy.

## S-022 (general)

A-Mem / MemoryOS / LangMem numbers cited in the survey are as re-measured inside RecMem and LightMem, not from A-Mem/MemoryOS/LangMem's own papers; the original A-Mem paper was not fetched, so its numbers remain attributed to RecMem/LightMem re-measurements.

## S-023 (general)

Uncertain: no single paper measures both consolidation regimes head-to-head under one protocol; USD costs are never reported anywhere (token counts only), so 'economics' in currency remains an inference; and whether consolidation-trigger heuristics (recurrence thresholds, buffer capacity, compression rate) generalize across domains is untested beyond the two benchmarks — RecMem's own limitations section flags this.

## S-024 (general)

What would settle the cost/economics question (unmet as of the survey): a single-paper, same-backbone, same-budget ablation of per-run extraction vs batch consolidation on both LoCoMo and LongMemEval-S reporting (a) construction + query tokens, (b) wall-clock including the offline pass, (c) accuracy by question type, and (d) USD cost at list API prices; no such head-to-head exists in the sources reached.

## S-025 (general)

Established verdict: eager per-run incremental extraction is measurably the expensive regime (RecMem cut construction tokens 87% on LoCoMo and 78% on LongMemEval-S vs Mem0/A-Mem at equal-or-better accuracy; LightMem cut total tokens 10x-38x and online-only tokens up to ~106x-117x vs eager baselines); a batch/offline pass has its own measured price (LightMem's OP-update roughly triples construction cost over online-only but is executed offline/parallel, keeping test-time latency ~3s-class and ~14x cheaper than eager construction); latency is where consolidation wins outright (Mem0 1.44s vs 17.1s p95, Zep ~90% cut at higher accuracy, sleep-time ~5x fewer test-time tokens to equal accuracy); the quality tradeoff is context-dependent — on short conversations full-context still beats selective systems (RecMem 72.47 vs FullContext 76.43 on LoCoMo), while on long (~100K+) contexts selective/batch systems win or tie at 1-2 orders of magnitude less cost.
