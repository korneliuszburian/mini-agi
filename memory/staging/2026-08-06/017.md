## S-000 (deterministic-verifier)

mini-agi ADR-0011: runs may declare two optional fields, `verify_command` (e.g. `make verify`, `npx tsc && node --test`) and `verify_target`; `mini-agi run verify <run.json>` executes the command in the target repo.

## S-001 (deterministic-verifier)

mini-agi verifier (crates/mini-agi-core/src/verifier.rs) runs `sh -c "<verify_command>"` with `current_dir(target_path)` and maps exit code vs claimed outcome: `verified` (gate passed AND run claims achieved), `verified-failed` (gate failed AND run claims failed), `disagrees` (mismatch), `unverified` (no verifier declared). A 120s timeout kills the process and reports `disagrees`.

## S-002 (deterministic-verifier)

mini-agi's verifier is audited for vacuity: `verify-audit` requires the gate to PASS on known-good work and FAIL on an empty counterfactual target, recording FPR/FNR.

## S-003 (deterministic-verifier)

mini-agi repo-wide gate is `scripts/verify.sh`; AGENTS.md binds `cargo test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` to it ('A pass you did not observe is a failed gate').

## S-004 (deterministic-verifier)

SWE-bench evaluates models by applying their generated patches to real-world repositories and running the repository's tests to verify if the issue is resolved, inside a containerized Docker environment.

## S-005 (deterministic-verifier)

SWE-bench instances carry FAIL_TO_PASS (tests resolved by the PR, which must pass after the patch) and PASS_TO_PASS (tests that must pass before and after); evaluation uses post-PR behavior as the reference solution.

## S-006 (deterministic-verifier)

Terminal-Bench/Harbor: each task is an instruction + a test script + an oracle solution; the Harbor format requires `tests/test.sh` to write a reward to `/logs/verifier/reward.txt` (e.g. `1`/`0`) or `reward.json`, with a canonical pytest-exit-code -> reward mapping. The verifier can run in a separate environment so proprietary grading code is hidden from the agent, and verifier and agent have separate `timeout_sec`.

## S-007 (deterministic-verifier)

Anthropic Claude Code guidance: 'Give Claude a check it can run: tests, a build, a screenshot to compare' — the check is 'anything that returns a signal' (test suite, build exit code, linter, diff-vs-fixture script, browser screenshot). This is vendor guidance/recommendation, not an observed benchmark result.

## S-008 (deterministic-verifier)

Anthropic Claude Code documents enforcement tiers for checks: in-prompt iteration; `/goal` condition re-checked by a separate evaluator every turn; a Stop hook that runs the check as a script and blocks the turn from ending until it passes (overridden after 8 consecutive blocks); and a verification subagent where a fresh model tries to refute the result so the worker isn't grading itself.

## S-009 (deterministic-verifier)

OpenAI Evals deterministic comparators: `basic/match.py` (`any([a.startswith(b) for b in B])`), `basic/includes.py` (`b in a`), `basic/fuzzy_match.py` (`a in b or b in a`), `basic/json_match.py` (JSON equality ignoring key order).

## S-010 (opinion)

Karpathy (opinion): 'Software 1.0 easily automates what you can specify. Software 2.0 easily automates what you can verify'; a verifiable environment must be resettable, efficient, and rewardable.

## S-011 (self-report-audit)

mini-agi: the run's `outcome.achieved` is the run's OWN claim until `mini-agi run verify <run.json>` confirms it; ADR-0011 records the prior state as 'The eval harness trusts run.json's self-reported outcome — nothing runs the work's own gate' and makes verification additive so a run without a verifier stays `unverified` with the report saying so explicitly.

## S-012 (self-report-audit)

mini-agi `verify_run` returns `unverified` with the excerpt 'no deterministic verifier declared (outcome is the run's own claim)' when no gate exists.

## S-013 (self-report-audit)

Voyager paper (arXiv:2305.16291) describes 'a new iterative prompting mechanism that incorporates environment feedback, execution errors, and self-verification for program improvement' — that self-verification is a designed component is established; the internal prompt mechanics were not read in full (abstract only).

## S-014 (self-report-audit)

Reflexion (arXiv:2303.11366): agents verbally reflect on task feedback signals; feedback may be various types (scalar values or free-form language) and sources (external or internally simulated).

## S-015 (self-report-audit)

OpenAI Evals: 'using the model to grade itself is a viable strategy for automated evaluation... the evaluation model and the model being evaluated don't have to be the same'; output is parsed from a steerable choice format, non-conforming output parses to `__invalid__`.

## S-016 (self-report-audit)

Anthropic multi-agent research system: research outputs are difficult to evaluate programmatically and LLMs are a natural fit; a single judge prompt scoring 0.0-1.0 plus a pass/fail grade was most consistent, and human evaluation catches what automation misses (e.g. hallucinated answers on unusual queries).

## S-017 (self-report-audit)

LATS (arXiv:2310.04406) integrates Monte Carlo Tree Search along with LM-powered value functions and self-reflections, with an environment for external feedback.

## S-018 (disagreement-handling)

mini-agi `disagrees` is a first-class outcome: verifier pass == claims achieved -> `verified`/`verified-failed`, otherwise `disagrees`; it is a judge-calibration signal with exit 1, and `loop verify` closes a gap only when the composite reaches the target AND the verifier passes — a self-reported outcome is not trusted when a verifier is available and disagrees.

## S-019 (disagreement-handling)

mini-agi `loop verify` keeps the claim held on disagreement (test: 'claim must stay held when the verifier disagrees').

## S-020 (disagreement-handling)

mini-agi monitors disagreement rate as judge-drift: `eval judge-drift` computes how often judged outcomes disagree with the deterministic layer against a calibration corpus; below a precision floor it appends a recalibration trigger to the audit log. ADR-0011 names Self-Taught Evaluators (arXiv:2408.02666) as the underlying idea.

## S-021 (disagreement-handling)

mini-agi's verifier-of-verifier audit records 'Recorded FPR/FNR per target in the calibration corpus' — disagreement diagnostics, not just pass/fail. Whether such verifier audits are common outside this repo is unverified; no primary source from another framework doing the same was found, likely a differentiator.

## S-022 (disagreement-handling)

OpenAI Evals `fact.yaml` model-graded eval returns distinct labels including 'D' for 'there is a disagreement between the submitted answer and the expert answer' and 'E' for 'the answers differ, but these differences don't matter'.

## S-023 (disagreement-handling)

SWE-bench counts `resolved` only when the post-patch repo passes the required tests, so the oracle can disagree with a solved-looking patch. The quantitative wrong-but-passing-patch numbers (~28.5% of a SWE-bench sample passes a Docker-verified incorrect patch; 7.8% of counted-correct patches fail the developer suite; one-in-five 'solved' patches semantically wrong) are estimates reported only in mini-agi's research doc citing preprints (2606.16062, 2503.15223, 2603.00520) that were not fetched — unconfirmed, flagged preprint; treat as calibration targets only after replication.

## S-024 (disagreement-handling)

Anthropic handles verifier disagreement by routing: in multi-agent research, a single LLM judge scored most consistent when eval test cases had a clear answer and the fix for edge cases was human evaluation plus prompt heuristics (source-quality), not a new scorer; Claude Code's Stop-hook gate has a bounded override (8 consecutive blocks ends the turn).

## S-025 (comparison)

Cross-framework comparison: mini-agi (verify_command/verify_target exit-code gate, outcome.achieved as run's own claim, unverified without gate, disagrees -> exit 1 + gap held + judge-drift calibration); SWE-bench (FAIL_TO_PASS/PASS_TO_PASS in Docker, patch is the artifact, no self-report, wrong-but-green patches the open failure mode); Terminal-Bench/Harbor (test.sh -> reward file, separate verifier env, tamper-sensitive evidence via sidecars); Claude Code (user-supplied check, Stop hook blocks turn with 8-block override, fresh subagent refutes); OpenAI Evals (deterministic comparators, LLM grades own output, D/E labels); Voyager/Reflexion/LATS (self-critique is the loop's own feedback signal, no separate judge).

## S-026 (evidence-status)

Let's Verify Step by Step (arXiv:2305.20050) establishes that step-level supervision beats outcome-only supervision for math reward models, but no production agent framework was found running step-level process supervision as its run verifier; mini-agi's plan lists it as roadmap, not shipped.
