## S-000 (general)

Codex's workspace-write sandbox protects <writable_root>/.git, .agents, and .codex as recursively read-only, so the agent cannot write its own config/skills even when the workspace is writable.

## S-001 (general)

Codex loads project-scoped config only after the project is trusted, and project config cannot override machine-local provider, auth, host-owned request metadata, notification, configuration-profile selection, or telemetry routing keys (model_provider, profiles, otel are ignored in project-local config.toml).

## S-002 (general)

Codex allow_managed_hooks_only = true in requirements.toml ignores user, project, and session hook configs while still allowing managed hooks; only honored in requirements.toml.

## S-003 (general)

Claude Code splits hard enforcement (permissions.deny, sandbox.enabled, forceLoginMethod — enforced by the client regardless of model decision; managed CLAUDE.md cannot be excluded by individual settings) from behavioral guidance (CLAUDE.md is context, not enforced configuration).

## S-004 (general)

Claude Code: memory/instructions are not a security boundary; to block an action regardless of what the model decides, use a PreToolUse hook.

## S-005 (general)

Claude Agent SDK evaluates every tool request in a fixed order: hooks → deny rules → ask rules → permission mode → allow rules → canUseTool callback.

## S-006 (general)

Claude Code deny rules block even in bypassPermissions mode; bare-name deny rules remove the tool from the model's context entirely; hooks run first and a hook deny applies even in bypassPermissions.

## S-007 (general)

Claude Code is fail-closed: unmatched commands default to requiring manual approval, and suspicious bash commands require manual approval even if previously allowlisted.

## S-008 (general)

Codex uses two layers: an OS-enforced sandbox (what is technically possible) plus an approval policy (when to ask), defaulting to macOS Seatbelt, Linux bwrap+seccomp, Windows native sandbox.

## S-009 (general)

Mini AGI runs deterministic gates before any LLM judge, and a run's outcome is its own claim until 'run verify' confirms it (verified before trusted, ADR-0011).

## S-010 (general)

OpenCode gates tools per call with allow/ask/deny plus structural guards: external_directory (default ask for paths outside the workspace) and doom_loop (prompts when the same tool call repeats 3 times with identical input).

## S-011 (general)

Claude Agent SDK canUseTool callback decides anything not resolved by rules/modes; AskUserQuestion and MCP tools marked anthropic/requiresUserInteraction always fall through to the callback even when an allow rule matches.

## S-012 (general)

OpenAI Agents SDK pauses a run for human review: tools can declare needsApproval: true; the run returns interruptions plus a resumable state, and the application approves or rejects pending items before resuming the same run.

## S-013 (general)

Codex approvals_reviewer = 'auto_review' routes eligible approvals through a reviewer subagent whose policy checks data exfiltration, credential probing, persistent security weakening, and destructive actions; low/medium-risk actions can proceed, critical-risk actions are denied, and prompt-build, review-session, and parse failures fail closed.

## S-014 (general)

Codex approval is granular per prompt category: approval_policy = { granular = { sandbox_approval, rules, mcp_elicitations, request_permissions, skill_approval } }, with skill_approval as its own gate.

## S-015 (general)

Workspace-trust dialogs gate loaded skills/config: Claude project skills take effect for allowed-tools only after the trust dialog is accepted, and a skill can grant itself broad tool access; Codex loads project config only when the project is trusted.

## S-016 (general)

Mini AGI makes memory writes human-signed: contested facts and dream-loop results route through memory signoff / a human queue (ADR-0010 signoff); the reviewer gate is human by design.

## S-017 (general)

Skills can restrict their own invocation and tools: disable-model-invocation: true (only the user can trigger, recommended for /deploy-style skills) and allowed-tools/disallowed-tools frontmatter.

## S-018 (general)

Vendors separate human-written memory (CLAUDE.md) from agent-written auto memory; both are loaded at the start of every conversation and treated as context, not enforcement.

## S-019 (general)

Claude Code auto memory is bounded: per-repo directory ~/.claude/projects/<project>/memory/, MEMORY.md index capped at the first 200 lines or first 25KB; writes over the limit return an error to rewrite the index; a modified ISO-8601 timestamp is stamped on frontmatter.

## S-020 (general)

Codex memories are opt-in generated state: off by default, stored under ~/.codex/memories/, treated as generated state not hand-edited, secrets redacted from generated fields; docs recommend keeping required rules in AGENTS.md and treating memories as a recall layer, not the sole source for rules that must always apply.

## S-021 (general)

Claude Code ships ConfigChange hooks that can audit or block settings changes during sessions.

## S-022 (general)

Mini AGI canonical memory is append-only with provenance on every entry: dated, carries a source, every fact id is sha256[:16]; derived views are generated, never hand-edited, and canonical wins on conflict.

## S-023 (general)

Mini AGI checkpoint journal records BEGIN/VERIFY-PASS/VERIFY-FAIL/CHECKPOINT-ABORT in memory/episodic/checkpoints.log; a red gate hard-resets to the last BEGIN commit (rollback always lands on the last checkpoint, ADR-0004); the journal must be repaired via checkpoint.sh, never through git.

## S-024 (general)

OpenAI Agents SDK guardrails are model-as-judge: input guardrails run before the main model, output guardrails validate final output, tool guardrails check arguments/results, and a tripwire blocks the run. Boundary caveat: input guardrails run only for the first agent in a chain and output guardrails only at the final-output agent, so checks belong next to the side-effecting tool in manager-style workflows.

## S-025 (general)

Claude Agent SDK: auto-approved tools never reach canUseTool, so for checks that must run on every call the docs prescribe a PreToolUse hook.

## S-026 (general)

Mini AGI reviewers must cite canonical fact ids they rely on; a verdict without memory anchors is flagged and gated (ADR-0003). The OWASP mapping attributes memory-poisoning mitigation to 'Append-only canonical with content-hash fact ids' and a provenance fingerprint in the audit (ADR-0014).

## S-027 (general)

Codex OTel records codex.tool_decision with approved/denied and source (configuration vs user), enabling post-hoc audit of who authorized each action.

## S-028 (general)

MCP spec: MCP itself cannot enforce security principles at the protocol level; hosts must obtain explicit user consent before invoking any tool, tool annotations should be considered untrusted unless obtained from a trusted server, and implementors SHOULD build robust consent and authorization flows.

## S-029 (general)

Mini AGI CI gate fails unless the runner identifies itself as isolated (non-root + RUNNER_NAME), so 'gate requires sandbox evidence' is literal (ADR-0009); the local worker runs under Landlock write-containment confined to workdir + its own state dir (ADR-0012).

## S-030 (general)

Claude skills option is a context filter, not a sandbox: unlisted skills are hidden from the model and rejected by the Skill tool, but their files remain on disk and are reachable through Read and Bash.

## S-031 (general)

Claude bypassPermissions mode gives full system access and allowed_tools does not constrain it (use with extreme caution); deny rules and hooks still bind.

## S-032 (general)

Replacing the claude_code preset with a custom system prompt drops the preset's security and safety instructions; built-in safety must be added.

## S-033 (general)

Codex yolo mode (--dangerously-bypass-approvals-and-sandbox) means no sandbox and no approvals; explicitly not recommended.

## S-034 (general)

Established synthesis: the dominant defense-in-depth pattern against self-modification is at the tool-call boundary — a fixed evaluation order (hooks → deny → ask → mode → allow → callback) with deny rules binding even in bypass modes (Claude), and a two-layer sandbox + approval-policy model (Codex).

## S-035 (general)

Established synthesis: self-modification of config/skills is stopped structurally — Codex makes the agent's own .codex and .agents dirs recursively read-only, project config is trust-gated and cannot override provider/auth/telemetry keys, and managed org config layers cannot be overridden by users or the agent.

## S-036 (general)

Established synthesis: self-modification of memory is bounded rather than blocked — memory stores are separate (user-written vs agent-written), opt-in, size-capped (Claude 200 lines/25KB), secret-redacting (Codex), and explicitly 'context, not enforcement', with deterministic enforcement delegated to hooks/settings.

## S-037 (general)

Established synthesis: provenance is used as a gate only in memory-anchored reviewer systems (mini-agi mandatory fact-id citations) and as audit evidence elsewhere (Codex tool_decision source field, Claude modified timestamps, mini-agi content-hash fact ids); MCP explicitly refuses protocol-level enforcement and defers to host consent flows.

## S-038 (general)

Uncertain: whether any framework enforces versioned rollback of its own config/skills automatically — only mini-agi showed a hard rollback journal (checkpoint BEGIN/VERIFY + reset to last green); vendor docs describe trust dialogs, permissions, and git-based incremental rollback but no enforced auto-rollback. Absence of evidence, not proof of absence.

## S-039 (general)

Uncertain: effectiveness data (bypass rates, tripwire precision) is not published in the docs reached; the 'judge alone ~45% vs judge+tools ~94%' figure appears only as a citation inside mini-agi's ADR-0003 and was not re-verified from its source paper.

## S-040 (general)
