## S-000 (general)

Generative Agents (Stanford 2023) perform batch reflection triggered when the sum of importance scores for latest events exceeds a threshold (150 in their implementation); in practice agents reflected roughly two or three times a day [S4]

## S-001 (general)

Generative Agents (Stanford 2023) technical evaluation (TrueSkill): no-reflection ablation scored μ=26.88 (σ=0.69), no-reflection-and-no-planning μ=25.64 (σ=0.68), crowdworker baseline μ=22.95, no-memory/no-reflection/no-planning μ=21.21; full architecture vs no-memory baseline gives Cohen's d=8.16; authors concluded 'each of these components is critical to strong performance' [S4]

## S-002 (general)

MemGPT uses scheduled timed events enabling it to run 'unprompted' without user intervention, plus event-driven batch operations on memory pressure [S1]

## S-003 (general)

MemGPT consolidates via queue manager recursive summarization: on memory pressure (warning at ~70% of context) the agent self-edits working/archival memory; at flush (~100%) it evicts ~50% of the window and generates a new recursive summary using the existing recursive summary and evicted messages [S1]

## S-004 (general)

MemGPT DMR accuracy was 93.4% (GPT-4 Turbo + MemGPT) vs 35.3% (recursive summarization alone); MemGPT reports no separate consolidation cost figures [S1]

## S-005 (general)

Letta sleep-time compute (2025) is idle-time batch consolidation, the closest published analogue to 'nightly'; a sleep-time agent owns the memory-edit tools and rewrites the primary agent's in-context memory blocks; frequency is configurable, higher frequency uses more tokens [S3]

## S-006 (general)

Letta sleep-time compute paper measured: ~5x reduction in test-time compute needed for the same accuracy on Stateful GSM-Symbolic and Stateful AIME; scaling sleep-time compute increases accuracy by up to 13% on Stateful GSM-Symbolic and 18% on Stateful AIME; on Multi-Query GSM-Symbolic average cost per query decreases 2.5x [S2]

## S-007 (general)

Zep/Graphiti performs per-message incremental ingestion: each episode triggers entity extraction (with prior n=4 messages for context), entity resolution, fact extraction, deduplication, temporal extraction, and LLM-based edge invalidation on contradictions; 'Graphiti consistently prioritizes new information' [S5]

## S-008 (general)

Zep/Graphiti design rationale: continuous dynamic community extension 'gradually diverge[s]' from a full label-propagation run so 'periodic community refreshes remain necessary', but the dynamic path exists because it 'significantly reduces latency and LLM inference costs' — continuous incremental for cost/latency, periodic batch recompute for quality [S5]

## S-009 (general)

Zep/Graphiti vs full-context baseline on LongMemEval (conversations ~115k tokens): accuracy +15.2% (gpt-4o-mini) and +18.5% (gpt-4o); latency 31.3s→3.20s and 28.9s→2.58s (approximately 90% reduction); context tokens 115k→1.6k [S5]

## S-010 (general)

Zep/Graphiti reported caveats: on DMR Zep scores 94.8% vs MemGPT's 93.4%, but the full-conversation baseline scored 94.4% (gpt-4-turbo) and 98.0% (gpt-4o-mini), so the DMR gap is within noise; Zep declined on single-session-assistant questions (−17.7% gpt-4o, −9.06% gpt-4o-mini) [S5]

## S-011 (general)

Mem0 performs incremental consolidation at write time: extraction runs per message pair and the update phase runs an LLM tool call per candidate fact choosing ADD / UPDATE / DELETE / NOOP; a separate async summary generation module periodically refreshes the conversation summary independent of the main processing pipeline [S6]

## S-012 (general)

Mem0 vs full-context on LOCOMO: full-context p95 latency ≈17.1s (p50 9.87s); Mem0 p50 0.708s / p95 1.440s; graph variant p50 1.091s / p95 2.590s; paper claims '91% lower p95 latency and saves more than 90% token cost' [S6]

## S-013 (general)

Mem0^g reached the highest LLM-judge score among memory systems on LOCOMO (J≈68.4 overall) with '26% relative improvements in the LLM-as-a-Judge metric over OpenAI'; on LOCOMO open-domain questions Zep beat Mem0 (J 76.60 vs 72.93) — a cross-vendor result, not batch-vs-continuous [S6]

## S-014 (general)

A-MEM performs per-interaction continuous evolution: each new interaction triggers note construction (LLM keywords/tags/context), top-k link generation, and 'memory evolution' rewriting the contextual representation of existing memories [S7]

## S-015 (general)

A-MEM cost: approximately 1,200 tokens per memory operation, an 85–93% token reduction vs LoCoMo and MemGPT (16,900 tokens); each operation costing less than $0.0003; 5.4s with GPT-4o-mini and 1.1s with locally-hosted Llama 3.2 1B; retrieval scales to 1M memories at 3.70 µs with linear storage [S7]

## S-016 (general)

A-MEM quality on DialSim: F1 3.45 vs LoCoMo 2.55 and MemGPT 1.18 [S7]

## S-017 (general)

No published batch-vs-continuous head-to-head exists: all measured quality/cost differences are within-system comparisons against full-context or RAG baselines; none of the sources reports the same system under both nightly-batch and continuous consolidation [S1-S7]

## S-018 (general)

Opinion (labeled as such in the source material): the closest evidence for the nightly-batch vs continuous trade-off is Zep's design claim that continuous dynamic extension trades graph quality (periodic refresh needed) for latency/LLM cost [S5]

## S-019 (general)

The term 'nightly' as such is not used by any source; closest analogues are '~2–3 times a day' reflection in Generative Agents and configurable idle-time compute in Letta [S4][S3]

## S-020 (general)

Verdict: established that two consolidation regimes exist (batch/scheduled: Generative Agents, MemGPT, Letta; continuous: Zep/Graphiti, Mem0, A-MEM) and reported differences are real but all within-system; uncertain whether nightly-batch vs continuous is directly answered in the literature — cost accounting is incomparable across papers (tokens vs latency vs USD, different benchmarks/models) [S1-S7]

## S-021 (general)

What would settle the batch-vs-continuous question: a controlled ablation running one system under per-event vs daily-batch consolidation on a fixed benchmark with identical token/latency metering, scored on a staleness-sensitive benchmark (e.g., LongMemEval knowledge-update/temporal categories); that study does not yet exist in the reached sources [S1-S7]
