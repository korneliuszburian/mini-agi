## S-000 (general)

Anthropic's engineering blog 'Effective context engineering for AI agents' (2025) asserts that giving the model less context is generally better: every unneeded token is both a confusion risk and a budget waste. Core techniques are context narrowing (retrieval pulling only relevant snippets), dynamic context assembly per call, entity memory/scratchpads, and summarization (a separate compression category for high-level understanding only). It warns against dumping full call transcripts into subagent calls. Source: https://www.anthropic.com/engineering/effective-context-engineering-for-agents

## S-001 (general)

MemGPT (Packer et al., arXiv:2310.08560, 2023) reports handling contexts exceeding the LLM context window by a factor of 10 while maintaining performance on dialogue and document analysis tasks, via OS-inspired tiered memory (main/external context) with selective retrieval ('paging'). The quantitative claim is the 10x context-window multiplier, not a directly measured token-cost reduction; token saving is the implied mechanism. Source: https://arxiv.org/abs/2310.08560

## S-002 (general)

HippoRAG (Gutiérrez et al., NeurIPS 2024, arXiv:2405.14831) reports on long-document QA (MuSiQue, 2WikiMultiHopQA, HotpotQA) that full-context baseline accuracy 'drops' as document length grows while the retrieval-based approach keeps accuracy higher at a fraction of the tokens. The reported numbers are accuracy figures (HippoRAG ~12-17% on MuSiQue vs SOTA ~35%+), not token-savings figures; cost reduction is stated qualitatively as 'more efficient'. Source: https://arxiv.org/abs/2405.14831

## S-003 (general)

Generative Agents (Park et al., UIST 2023, arXiv:2304.03442) uses a memory stream with retrieval by recency/importance/relevance, and observations summarized on the fly into higher-level reflections stored back into the stream. No token-savings numbers are reported; the mechanism keeps only salient memories in context. Source: https://arxiv.org/abs/2304.03442

## S-004 (general)

LLMLingua (Jiang et al., Microsoft, EMNLP 2023, arXiv:2310.05736) reports coarse-to-fine prompt compression achieving a ratio up to 20x with minimal performance loss (budgets 1x/3x/5x/10x/20x), with measured savings in compressed token count and FLOPs reduction. It targets whole prompts (demonstrations, instructions, chain-of-thought), not agent memory. Source: https://arxiv.org/abs/2310.05736

## S-005 (general)

Anthropic Agent SDK documentation describes 'message injection' as the default context-assembly strategy for long-running agents: the last N messages verbatim ('recent context') plus everything older collapsed into a summary attached to each call. Context per turn is bounded rather than growing unboundedly. The SDK-specific wording is marked uncertain: the SDK docs page could not be fully loaded in that environment; existence and general description were verified via the 'Effective context engineering' article. Source: https://docs.claude.com/en/api/agent-sdk/context

## S-006 (general)

Across the sources reviewed, token 'waste' is framed two ways: (a) paid-token waste (input tokens billed per call times repeated calls in a long loop) and (b) accuracy waste (irrelevant context degrading performance). Industry guidance (Anthropic) ranks retrieval-first narrowing above full-context for accuracy and cost, uses summaries only when high-level understanding suffices, and warns that compression touching full transcripts is lossy.

## S-007 (general)

No single primary study directly A/Bs selective retrieval vs summary vs compression vs full-context and reports token savings as the outcome metric for long-running agents was found; each source reports a different metric (accuracy at fixed context, context-window multiplier, compression ratio, per-call context bounds). Settling evidence would be a controlled experiment on a long-running agent benchmark (e.g., SWE-bench agentic runs or long-horizon tool use) measuring billed input tokens and task success across the four arms with identical model and task; to the reviewer's knowledge no such published benchmark exists.
