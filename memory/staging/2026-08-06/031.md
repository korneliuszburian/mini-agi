## S-000 (general)

Production systems converge on three-tier context strategy: (1) prune redundant layer first (stale tool outputs), (2) summarize/compact conversation to decision-level summary, (3) move evidence out of the window (persisted transcripts, memory tools, subagents) rather than destroying it. Each tier's loss profile is documented by its vendor.

## S-001 (general)

Compaction is defined as 'taking a conversation nearing the context window limit, summarizing its contents, and reinitiating a new context window with the summary'; in Claude Code the model is passed history to 'summarize and compress the most critical details... preserving architectural decisions, unresolved bugs, and implementation details while discarding redundant tool outputs or messages', continuing with compressed context plus the five most recently accessed files. (Anthropic Engineering, effective-context-engineering, 2025-09-29)

## S-002 (general)

Claude Code operational definition of compaction: 'Older tool outputs are cleared first, then the conversation is summarized.' (Claude Code Glossary)

## S-003 (general)

Summarization = LLM-written prose condensation of messages; in Anthropic stack it is the engine inside compaction; OpenAI offers it as a distinct cookbook pattern.

## S-004 (general)

Pruning/truncation = dropping raw transcript items (tool results, old turns, unplayed audio) without replacing them with a summary.

## S-005 (general)

Claude Agent SDK auto-compacts when context window approaches limit: emits a compact_boundary message; a PreCompact hook allows archiving the full transcript before summarizing — the documented way to keep evidence. (Claude Agent SDK, agent-loop)

## S-006 (general)

Claude Code structured summary keeps: requests and intent, key technical concepts, files examined/modified with important code snippets, errors and how they were fixed, pending tasks, current work; it replaces verbatim conversation — full tool outputs and intermediate reasoning are gone. Detailed instructions from early in conversation may be lost; persistent rules belong in CLAUDE.md. (Claude Code docs)

## S-007 (general)

After Claude Code compaction, project CLAUDE.md, auto memory, and MCP tools reload; the skill listing is the one startup item not re-injected.

## S-008 (general)

Claude Code context-window simulation models the summary at ~12% of the summarized token count — illustrative, not a measurement.

## S-009 (general)

Evidence is not destroyed, only removed from the model-visible window: every Claude Code session transcript is written to a JSONL file under ~/.claude/projects/; the SDK can mirror transcripts to S3/Redis so any host can resume.

## S-010 (general)

Prompt-cache economics: compaction invalidates the cached conversation prefix by design; a warm mid-session /compact reads the prefix from cache so it 'costs a fraction of what the context size suggests'; /rewind reuses an already-cached prefix; after long breaks Claude Code offers 'resume from a summary'. (Claude Code prompt-caching docs)

## S-011 (general)

OpenAI compaction is server-side (context_management: [{type:'compaction', compact_threshold:200000}] or /responses/compact endpoint) and returns an 'encrypted compaction item that carries forward key prior state and reasoning into the next run using fewer tokens... opaque and not intended to be human-interpretable' plus retained items; you must not prune the output, and with previous_response_id chaining 'do not manually prune'. (OpenAI Compaction guide)

## S-012 (general)

Contrast: Anthropic's compaction output is a readable structured summary; OpenAI's is an opaque encrypted state item whose fidelity is unquantified in the doc.

## S-013 (general)

Anthropic warns 'overly aggressive compaction can result in the loss of subtle but critical context'; guidance is to 'Start by maximizing recall to ensure your compaction prompt captures every relevant piece of information from the trace, then iterate to improve precision.' (Effective context engineering)

## S-014 (general)

Anthropic treats tool-result clearing ('context editing') as 'one of the safest lightest touch forms of compaction'.

## S-015 (general)

LoCoMo found session summaries as context do not significantly improve performance despite high recall accuracies, 'likely due to loss of information during the conversion of dialogs to summaries'; retrieval of raw observations did help (+5% for top-5 retrieved); incremental summarization was strongest for event summarization. (Maharana et al., arXiv:2402.17753)

## S-016 (general)

LoCoMo long-context QA: gpt-4-turbo scored 32.4 vs human 87.9; a 16k-context model fell to 2.1% on adversarial questions while a 4k-context model got 70.2%. (arXiv:2402.17753)

## S-017 (general)

OpenAI Cookbook has a transcript-summarization example for Realtime sessions (Context_summarization_with_realtime_api.ipynb) — existence/path verified via GitHub API; content not read.

## S-018 (general)

Token-window truncation is the default failure mode and lossy by definition: 'Tokens generated in excess of the context window limit may be truncated in API responses.' (OpenAI Conversation state docs)

## S-019 (general)

Claude platform context editing 'automatically clears stale tool calls and results from within the context window when approaching token limits... removing stale content while preserving the conversation flow.' (claude.com/blog/context-management)

## S-020 (general)

OpenAI Realtime conversation.item.truncate cuts audio and removes the text transcript for the unplayed portion; OpenAI explicitly states it does not produce a truncated transcript.

## S-021 (general)

Lost in the Middle (Liu et al., TACL 2023): models use beginning and end of context best; 'performance is often highest when relevant information occurs at the beginning or end... and significantly degrades when models must access relevant information in the middle.' Supports pruning the middle over pruning oldest turns.

## S-022 (general)

Structured note-taking/agentic memory: the agent regularly writes notes persisted to memory outside the context window, pulled back into the window at later times; memory tool keeps key findings and project state across sessions out of the window. (Effective context engineering; context-management blog)

## S-023 (general)

Subagent architectures bound context growth to a summary: a subagent 'returns only a condensed, distilled summary of its work (often 1,000–2,000 tokens)' and the main agent's context grows by that summary, not the full subtask transcript.

## S-024 (general)

MemGPT formalized OS-style virtual context management: 'intelligently manages different memory tiers... providing extended context within the LLM's limited context window.' (Packer et al., arXiv:2310.08560)

## S-025 (general)

As reported by a second research group (vendor evaluation, not MemGPT's own paper): 'The MemGPT framework currently leads performance metrics with 93.4% accuracy using gpt-4-turbo, a significant improvement over the 35.3% baseline achieved through recursive summarization' on Deep Memory Retrieval; the same paper reports its own system at 94.8% on DMR and gains 'up to 18.5%' with ~90% latency reduction on LongMemEval using a non-lossy episodic store. (Rasmussen et al., Zep, arXiv:2501.13956)

## S-026 (general)

Anthropic vendor-internal evals (published in launch post, methodology internal and not reproducible — treat as claims): combining memory tool with context editing improved performance by 39% over baseline; context editing alone 29%; in a 100-turn web-search eval context editing finished workflows that would otherwise fail due to context exhaustion while reducing token consumption by 84%. (claude.com/blog/context-management)

## S-027 (general)

Chroma context rot (18 models, Jul 2025): significantly higher performance on focused prompts (~300 tokens) vs full prompts (~113k tokens) on LongMemEval; distractor effects amplify with length; even simple tasks degrade as input grows. Supports pruning irrelevant context rather than growing the window.

## S-028 (general)

No public apples-to-apples benchmark runs the same agent traces through naive truncation vs LLM summarization vs compaction vs retrieval and reports fact-recall side by side; vendor numbers are directional evidence, not a ranking. What would settle it: a neutral benchmark with fixed transcripts, identical inputs across methods, and both downstream task success and fact-recall metrics.
