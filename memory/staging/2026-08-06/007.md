## S-000 (general)

No system in the surveyed literature uses a literal "nightly cron"; "nightly" is approximated by daily-frequency batch reflection (Generative Agents) and idle-time scheduled consolidation (Letta sleep-time compute), while continuous background consolidation is approximated by per-event incremental ingestion (Zep/Graphiti, Mem0, A-MEM).

## S-001 (general)

Generative Agents (Stanford 2023) batch reflections are generated when the sum of importance scores for the latest perceived events exceeds a threshold of 150; in practice the agents reflected roughly two or three times a day [S4] §4.2.

## S-002 (general)

Generative Agents ablation (TrueSkill): no-reflection μ=26.88 (σ=0.69), no-reflection-and-no-planning μ=25.64 (σ=0.68), crowdworker baseline μ=22.95, no-memory/no-reflection/no-planning μ=21.21; full architecture vs no-memory baseline gives Cohen's d=8.16; authors conclude "each of these components is critical to strong performance" [S4] §5.

## S-003 (general)

MemGPT uses "timed events that are run on a regular schedule (allowing MemGPT to run 'unprompted' without user intervention)" [S1] §2.4.

## S-004 (general)

MemGPT consolidation is the queue manager's recursive summarization: on memory pressure (warning at ~70% of context) the agent self-edits working/archival memory; at flush (~100%) it evicts ~50% of the window and "generates a new recursive summary using the existing recursive summary and evicted messages" [S1] §2.2.

## S-005 (general)

MemGPT DMR accuracy 93.4% (GPT-4 Turbo + MemGPT) vs 35.3% (recursive summarization alone) [S1] §3.1.1; MemGPT reports no separate consolidation cost figures.

## S-006 (general)

Letta sleep-time compute (2025) is idle-time batch consolidation: two agents, the sleep-time agent owns the memory-edit tools and rewrites the primary agent's in-context memory blocks; it is "the closest published analogue to 'nightly'" [S3].

## S-007 (general)

Letta sleep-time memory formation is explicitly contrasted with MemGPT's incremental form: "Sleep-time agents on the other hand can continuously improve their learned context to generate clean, concise, and detailed memories" [S3].

## S-008 (general)

Letta sleep-time frequency is configurable: "The higher the frequency setting, the more tokens your agent will use" [S3].

## S-009 (general)

Letta measured effect (paper): "sleep-time compute can reduce the amount of test-time compute needed to achieve the same accuracy by ~5x on Stateful GSM-Symbolic and Stateful AIME and ... scaling sleep-time compute we can further increase accuracy by up to 13% on Stateful GSM-Symbolic and 18% on Stateful AIME"; on Multi-Query GSM-Symbolic "we can decrease the average cost per query by 2.5x" [S2] abstract.

## S-010 (general)

Zep/Graphiti dynamic community extension "gradually diverge[s]" from a full label-propagation run, so "periodic community refreshes remain necessary"; the dynamic path exists because it "significantly reduces latency and LLM inference costs" [S5] §2.3; design rationale is continuous incremental updates for cost/latency, periodic batch recompute for quality.

## S-011 (general)

Zep/Graphiti per-message ingestion: each episode triggers entity extraction (with prior n=4 messages for context), entity resolution, fact extraction, deduplication, temporal extraction, and LLM-based edge invalidation on contradictions; "Graphiti consistently prioritizes new information" [S5] §2.1–2.2.

## S-012 (general)

Zep vs full-context baseline on LongMemEval (~115k token conversations): accuracy +15.2% (gpt-4o-mini) and +18.5% (gpt-4o); latency 31.3s→3.20s and 28.9s→2.58s ("reducing response times by approximately 90%"); context tokens 115k→1.6k [S5] §4.3.2.

## S-013 (general)

Zep caveats the paper itself reports: on DMR Zep scores 94.8% vs MemGPT's 93.4% but the full-conversation baseline scored 94.4% (gpt-4-turbo) and 98.0% (gpt-4o-mini), so the DMR gap is within noise; Zep declined on single-session-assistant questions (−17.7% gpt-4o, −9.06% gpt-4o-mini) [S5] §4.2, §4.3.2.

## S-014 (general)

Mem0 does incremental consolidation at write time plus an async background summarizer: extraction runs per message pair; the update phase runs an LLM tool call per candidate fact choosing ADD / UPDATE / DELETE / NOOP; the "asynchronous summary generation module that periodically refreshes the conversation summary ... operates independently of the main processing pipeline" [S6] §2.1.

## S-015 (general)

Mem0 cost vs full-context on LOCOMO: full-context p95 latency ≈17.1s (p50 9.87s); Mem0 p50 0.708s / p95 1.440s; graph variant p50 1.091s / p95 2.590s; paper claims "91% lower p95 latency and saves more than 90% token cost" vs full-context [S6] abstract, §4.4.

## S-016 (general)

Mem0^g reaches the highest LLM-judge score among memory systems (J≈68.4 overall); "26% relative improvements in the LLM-as-a-Judge metric over OpenAI" [S6] abstract, §4.4.

## S-017 (general)

On LOCOMO open-domain questions Zep beat Mem0 (J 76.60 vs 72.93) — a cross-vendor result, not a batch-vs-continuous one [S6] §4.1.3.

## S-018 (general)

A-MEM (2025) does per-interaction continuous evolution: each new interaction triggers note construction (LLM keywords/tags/context), top-k link generation, and "memory evolution" that rewrites the contextual representation of existing memories [S7] §3.1–3.3.

## S-019 (general)

A-MEM cost: "approximately 1,200 tokens per memory operation, achieving an 85–93% reduction in token usage compared to baseline methods (LoCoMo and MemGPT with 16,900 tokens)"; "each memory operation costing less than $0.0003"; processing "5.4 seconds using GPT-4o-mini and only 1.1 seconds with locally-hosted Llama 3.2 1B" [S7] §4.3.

## S-020 (general)

A-MEM retrieval scales to 1M memories at 3.70 µs with linear storage [S7] §4.6; on DialSim F1 3.45 vs LoCoMo 2.55 and MemGPT 1.18 [S7] §4.3.

## S-021 (general)

No published batch-vs-continuous head-to-head exists: all measured quality/cost differences in [S1]–[S7] are within-system comparisons against full-context or RAG baselines; none of the sources reports the same system under both nightly-batch and continuous consolidation; the closest evidence for the trade-off is Zep's design claim that continuous dynamic extension trades graph quality (periodic refresh needed) for latency/LLM cost [S5] §2.3.

## S-022 (general)

Cost accounting is incomparable across papers (tokens vs latency vs USD, different benchmarks/models).

## S-023 (general)

"Nightly" as such is not used by any source; the closest are "~2–3 times a day" ([S4]) and configurable idle-time ([S3]).

## S-024 (general)

A controlled ablation running one system under per-event vs daily-batch consolidation on a fixed benchmark with identical token/latency metering, scored on a staleness-sensitive benchmark (e.g., LongMemEval knowledge-update/temporal categories), does not yet exist in the sources reached.

## S-025 (general)

The full-architecture μ value in the Generative Agents technical evaluation fell in a section the fetch truncated; only ordering and the Cohen's d are quoted for it [S4].
