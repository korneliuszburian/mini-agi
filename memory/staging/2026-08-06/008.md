## S-000 (general)

LangSmith annotation queues group runs or whole threads, prescribe a rubric ("Instructions" + feedback keys), and track reviewer progress; queues present one item at a time ("single-run") or two runs side-by-side ("pairwise"), with item states Needs Review → Needs Others' Review → Completed.

## S-001 (general)

LangSmith annotation-queue collaborator settings let an item be held until every workspace member marks it Done, or require a set number of reviewers per run, and can name assigned reviewers explicitly; reservations lock an item to a reviewer for a set time and expire/release it if the reviewer leaves without marking Done, so the number of items visible to each reviewer can differ from the total queue size.

## S-002 (general)

Langfuse annotation queues require a Score Config defining scoring dimensions, can be assigned to users, accept traces/observations/sessions singly or in bulk, and are processed fully keyboard-driven (navigation + scoring keys).

## S-003 (general)

Braintrust human review defines review scores (categorical, continuous, free-form) that appear in logs/experiments/datasets, and manages review work via a dedicated Review page with views (Awaiting review, Assigned to me, Completed), SQL filtering, and a kanban layout (Backlog / Pending / Complete); rows can be assigned to team members who get email (and optional Slack DM) notifications.

## S-004 (general)

Braintrust stores each reviewer's scores independently; continuous/categorical scores are averaged on the parent span, free-form scores require a reviewer (or admin) to pick a value via "Set as base span value", and an "N total reviews" indicator shows agreement vs. divergence; Braintrust explicitly does not support blind review.

## S-005 (general)

LangSmith's per-run reviewer thresholds and reservation locking prevent two reviewers from grading the same comparison simultaneously in pairwise queues.

## S-006 (general)

LangSmith automation rules are defined as filter + sampling rate (0–1) + action, with actions including Add to annotation queue, Add to dataset, Trigger webhook, Extend data retention, run online evaluator, and Trigger alert, in a fixed ordering (queue → dataset → webhook → evaluator → alert); documented examples include sending all traces with negative feedback or 10% of all traces to an annotation queue for spot checks.

## S-007 (general)

LangSmith docs suggest routing runs that already carry user feedback (e.g., thumbs-down) into an annotation queue for triage.

## S-008 (general)

Braintrust Topics auto-classifies production logs by task, sentiment, issue type, and custom patterns; logs can be filtered by topic classification (SQL on classifications.Task.label, etc.), matching logs assigned to reviewers, and topic-matching scorers run online with a sampling rate via automations.

## S-009 (general)

Datadog Agent Observability "Patterns" performs automated hierarchical topic clustering of production traffic to surface user intents and coverage gaps; "Insights" runs outlier detection across span name, workflow type, and Patterns topics, surfacing anomalies in the UI for the selected time window.

## S-010 (general)

LangSmith Engine automatically detects recurring issues in traces, diagnoses root cause, and proposes resolution, as an alternative to manually triaging every failed run.

## S-011 (general)

LangGraph implements HITL via dynamic interrupts: the graph pauses at interrupt(...), returns an interrupt payload to the caller, and resumes by posting a Command(resume=...) with the human's input; static interrupts (interrupt_before/after) exist but the docs recommend against them for HITL, calling them debug/test tools.

## S-012 (general)

LangGraph time travel lets an operator list checkpoints (get_history), mutate state (update_state), and resume from the edited checkpoint.

## S-013 (general)

LangSmith alerts are threshold-based on aggregated metrics (run count, cost, errors count or %, average feedback score, latency) over a configurable 5 or 15 minute window, are project-scoped, can be further scoped by a filter builder (status/run type/tag/error), and route to Slack, PagerDuty, Dynatrace, or any webhook.

## S-014 (general)

LangSmith alert noise controls documented in-source are PagerDuty dedup (to receive the same alert again within an hour you must resolve the active incident) and a webhook payload alert_rule_id documented as a de-duplication key in the webhook service; best practices listed are starting with broader thresholds, adjusting sensitivity to criticality, and routing to appropriate on-call.

## S-015 (general)

Langfuse monitors are a severity state machine (OK / WARNING / ALERT / NO_DATA / PAUSED); alerts fire only on severity transitions, Renotify is off by default (re-firing every N minutes only if enabled), and no-data handling can suppress alerts (keep previous severity, show NO_DATA with no alert, or delayed sustained-NO_DATA alert); notifications go through Automations to Slack, HMAC-signed webhook, or GitHub Actions.

## S-016 (general)

Braintrust's anti-noise mechanism is a beta daily "Topics digest" posted once a day to Slack covering the previous 24h — summary of activity shift, biggest topic mover, highlight traces, and one takeaway — rather than per-event alerts.

## S-017 (general)

Braintrust score visibility can restrict scores to specific members/groups or show them conditionally (e.g., only when a triage score indicates deeper review is needed), and is documented as a display filter, not an access control.

## S-018 (general)

OpenAI Agents SDK reduces captured volume rather than notification volume: tracing is on by default but can be disabled per-run, sensitive-data capture (trace_include_sensitive_data) can be turned off, and custom/sampled trace processors can be installed in place of the default exporter.

## S-019 (general)

OpenAI Agents SDK supervises concurrent agents via grouping: traces carry workflow_name and an optional group_id to link multiple traces from one conversation (e.g., a chat thread id), giving a conversation-scoped view rather than per-call noise.

## S-020 (general)

Langfuse sessions group traces/observations into one session for replay of the full interaction.

## S-021 (general)

HumanLayer's original HITL-API product is deprecated — the repo README states "the code here is pretty much all deprecated"; the current product (humanlayer.com) is an AI-coding IDE whose marketing positions task/session grouping, real-time session visibility, and cloud daemons as the way to supervise many parallel agent sessions. Only the marketing homepage and repo README were verified; no detailed supervision-docs were reachable (docs.humanlayer.dev transport-error), and its efficacy as a supervision console is an unverified opinion.

## S-022 (general)

No vendor documentation was verified that quantifies how much notification noise these controls actually reduce — no measured alert-fatigue data was found in primary docs, and no claim about effectiveness is made.

## S-023 (general)

Arize Phoenix was reached only at its overview (tracing → evals → datasets → experiments); no HITL review-queue or alerting page was found, so Phoenix is not claimed as a review-queue tool.

## S-024 (general)

The HITL review-queue surface is standard across LangSmith, Langfuse, and Braintrust: rubric-driven queues over traces/sessions, reservation/locking, reviewer-count or assigned-reviewer completion, and multi-reviewer consensus handling.

## S-025 (general)

Attention routing into HITL queues is overwhelmingly pre-filtering rather than pushing every trace at a human: rule + sampling-rate automations route a fraction of filtered runs into queues (LangSmith), and topic/issue classification feeds assignment and online scoring (Braintrust Topics, Datadog Patterns/Insights, LangSmith Engine).

## S-026 (general)

Notification-noise reduction is documented as threshold aggregation + severity state machines + transition-only firing + dedup keys + daily digest (LangSmith alerts, Langfuse monitors, Braintrust Topics digest), not as per-trace paging.

## S-027 (general)

For supervising parallel agents, grouping surfaces (OpenAI group_id/workflow_name, Langfuse sessions, HumanLayer task/session views) are the documented answer; effectiveness of these mechanisms is unmeasured inference, not a primary-source claim.
