## S-000 (general)

DMR (Deep Memory Retrieval) is a task introduced in the MemGPT paper, built on the Multi-Session Chat (MSC) dataset; the agent is asked a question referring back to a prior conversation with a very narrow expected answer range, with QA pairs generated by a separate LLM instructed to write questions answerable only from the old chat log and not contained in persona information.

## S-001 (general)

DMR/MSC setup: MSC conversations have five sessions of ~12 messages, plus a new session 6 containing one QA pair; Zep reports DMR as a 500-conversation subset of MSC. Metrics are ROUGE-L plus an LLM judge scoring CORRECT/WRONG. Reported accuracies: GPT-3.5 Turbo 38.7% -> MemGPT 66.9%; GPT-4 32.1% -> 92.5%; GPT-4 Turbo 35.3% -> 93.4%.

## S-002 (general)

DMR measures single-session-hop fact recall (opinion grounded in source): whether an agent can pull one specific fact out of a prior session; it tests retrieval/consistency, not updating, temporal reasoning, or abstention. Zep's primary text criticizes it: 'The evaluation relies exclusively on single-turn, fact-retrieval questions... Each conversation contains only 60 messages, easily fitting within current LLM context windows.'

## S-003 (general)

LoCoMo is a dataset of very long-term conversations, each ~300 turns and ~9K tokens on avg. over up to 35 sessions, 50 dialogues, generated via a machine-human pipeline grounded in personas and temporal event graphs, including multimodal (image-sharing) turns.

## S-004 (general)

LoCoMo has three tasks: (1) QA in five categories — single-hop, multi-hop, temporal reasoning, open-domain (commonsense/world) knowledge, and adversarial (designed to trick the agent into providing wrong answers, with expectation the agent identifies them as unanswerable); (2) event-graph summarization scored with FactScore against the ground-truth temporal event graph; (3) multi-modal dialogue generation scored with MMRelevance.

## S-005 (general)

LoCoMo findings: long-context LLMs/RAG improve QA 22–66% but significantly lag human levels (by 56%), especially in temporal reasoning (by 73%); long-context models are especially prone to misassigning dialogs or events to the wrong speaker; gpt-3.5-turbo-16k scored 2.1% on adversarial questions. RoMem later classifies LoCoMo as the 'hybrid' benchmark: a mixture of dynamic temporal updates and general knowledge queries.

## S-006 (general)

LongMemEval: 500 manually curated questions over task-oriented user-assistant histories evaluating five abilities — information extraction (IE), multi-session reasoning (MR), temporal reasoning (TR), knowledge updates (KU), and abstention (ABS); seven question types; two standard settings: LongMemEval_S (~115k tokens/question) and LongMemEval_M (500 sessions, ~1.5M tokens).

## S-007 (general)

LongMemEval KU definition: 'Ability to recognize the changes in the user's personal information and update the knowledge of the user dynamically over time.' KU error analysis states the retriever was only able to identify the updated knowledge but failed to retrieve the previous information before update, counted as retrieval failure.

## S-008 (general)

LongMemEval findings: long-context LLMs drop 30–60% vs. oracle retrieval on LongMemEval_S; commercial ChatGPT and Coze dropped 37% and 64% vs. offline reading; ChatGPT tended to overwrite crucial information as chat continues, while Coze often failed to record indirectly provided user information.

## S-009 (general)

On knowledge-update and temporal reasoning: LongMemEval authors report 'Naive time-agnostic memory designs perform poorly on temporal reasoning questions'; time-aware indexing/query expansion improves temporal-reasoning recall by 6.8–11.3%; KU questions require retrieving BOTH pre-update and post-update evidence, with a store that drops the older fact counted as failed retrieval.

## S-010 (general)

Static-dynamic dilemma (RoMem primary text): 'most existing approaches model time as discrete metadata, either sorting by recency (burying old-yet-permanent knowledge), simply overwriting outdated facts, or requiring an expensive LLM call at every ingestion step, leaving them unable to distinguish persistent facts from evolving ones.' Failure directions: recency sorting silently buries static knowledge (decades-old fact ranked below fresher irrelevant entries); disabling recency bias leaves temporal conflicts unresolved, confusing the downstream LLM. RoMem asserts its append-only store works only because contradictions are resolved geometrically at query time, and claims all existing baselines (Mem0, Zep, LicoMemory, HippoRAG) treat memory as a static snapshot, causing contradictory facts to cluster together in retrieval space and confuse the LLM.

## S-011 (general)

RoMem cross-benchmark numbers (single-paper, author-reported): LoCoMo Recall@10 (GPT-5-mini impl.) — Mem0 temporal 0.690, HippoRAG 0.645, Zep 0.553, A-Mem 0.691, RoMem 0.726; DMR-MSC MRR — Mem0 0.847, HippoRAG 0.848, RoMem 0.856, with naive-recency handling claimed to be precisely the behaviour naive recency-based approaches would destroy for static fact retrieval.

## S-012 (general)

Detail-level extraction: fact-extraction compression trades recall of detail — 'While further compression into individual user facts harms overall performance due to information loss, it improves the multi-session reasoning accuracy.' LoCoMo likewise: session-summary RAG does not improve QA, likely due to loss of information during conversion of dialogs to summaries.

## S-013 (general)

Adversarial/abstention failures: facts never stored can't be abstained on — Coze often failed to record indirectly provided user information (implicitly-stated facts never enter the store), and compressed/overwriting stores corrupt prior facts over time (ChatGPT); LoCoMo's adversarial category (2.1% for a long-context model) is the same failure surface.

## S-014 (general)

DMR is the task where a static fact store succeeds: it has no update, temporal, or abstention categories, and Zep shows a plain full-conversation baseline already matches MemGPT (94.4% vs 93.4%, both gpt-4-turbo; Zep 94.8%). Hence high DMR scores co-exist with failures on LongMemEval/LoCoMo.

## S-015 (general)

Uncertain/estimated: RoMem's cross-benchmark numbers use a different metric than the original LoCoMo paper (Recall@10 over ~1,986 QA pairs vs. the original paper's F1 answer prediction over 50 dialogues); LoCoMo question count differs across sources (1,813 in one 2026 paper vs. 1,986 in RoMem). Zep's LongMemEval improvements (up to +18.5% accuracy, −90% latency) are vendor self-reported. No primary source reached gives a controlled head-to-head of a 'pure' append-only store vs. an updating store on all three benchmarks with an identical LLM judge.

## S-016 (general)

Evidence that would settle the append-only vs. updating-store question: an independent evaluation running the same underlying model against (a) a plain append-only fact/vector store, (b) an updating/invalidating store (e.g., temporal KG), and (c) full-context reading, on LongMemEval (per question-type: KU, TR, ABS) and LoCoMo (temporal, adversarial) with a fixed judge. LongMemEval repo (github.com/xiaowu0162/LongMemEval) and RoMem's reported protocol are the two ready-made harnesses.

## S-017 (general)

Verdict synthesis: DMR (MemGPT, 2023) measures single-session-hop fact recall on short 5-session MSC chats and is near-saturated (full-context baseline matches the memory system); LoCoMo (2024) measures long-horizon QA across single/multi-hop, temporal, open-domain, and adversarial questions plus event-summarization, with temporal reasoning and abstention the hardest axes (human 87.9 F1 vs. best model ~37.8; long-context adversarial 2.1%); LongMemEval (ICLR 2025) explicitly measures IE, MR, TR, KU, ABS at 115k–1.5M-token scales, documenting 30–60% drops for long-context LLMs and 37–64% drops for commercial memory assistants.
