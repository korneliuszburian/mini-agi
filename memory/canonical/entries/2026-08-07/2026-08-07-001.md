## F-000 `cfa462ba820abdc5`

PromptPort (Kotte, arXiv:2601.06151) formalizes cross-model "format collapse": structured extraction fails in production not because models lack understanding but because output formatting is unreliable across models/prompts — the same prompt returns clean JSON on GPT-4 but fenced/prose-wrapped/malformed output on Llama, so strict parsers reject otherwise-correct extractions. Introduces dual metric separating failure layers: ROS (strict parsing) vs CSS (post-canonicalization); on a 37,346-example camera-metadata benchmark across six model families it found severe format collapse (Gemma-2B ROS 0.116 vs CSS 0.246) and large cross-model portability gaps (0.4–0.6 F1). Recovery via deterministic canonicalization + DistilBERT verifier (safe-override, explicit abstention) recovers +6–8 F1, verifier-driven selection adds +14–16 F1, approaching per-field oracle (0.890 vs 0.896 zero-shot) without modifying base models, generalizing to held-out families.

## F-008 `ef6a82f7cb4bf553`

XGrammar (arXiv:2411.15100, MLSys '25): CFG mask-generation cost can go below the LLM's own per-token latency — under 40 µs/token for JSON Schema and unconstrained JSON (Llama-3.1-8B, RTX 4090), up to 3x speedup on JSON Schema and 100x on CFG vs baselines, up to 80x end-to-end on H100; near-zero overhead with CPU/GPU overlap. ## F-009 `e2c28a05b7ee21b1`

PSC / Parser Stack Classification (arXiv:2608.03065, ISSTA 2026) makes GCD mask computation vocabulary-independent: the set of parser stacks accepting a token is a regular language, so a single precompiled FSA classifies the parser stack once per step (O(1) mask lookup). Measured vs XGrammar/GreatGramma/Formatron/LLGuidance: mask computation up to 700x faster on complex PL grammars (Java/Go/SQL), up to 30x on schema-conformant JSON, end-to-end throughput approaching unconstrained decoding with correctness on par (99.6–100% processed, no parser errors). Preprocessing cost is small for simple grammars, significant for complex ones; results shareable across users.

## F-010 `2df44a2e25263275`

Locally constrained decoding (LCD — the Outlines/XGrammar/OpenAI stack) is distribution-biased and does not guarantee constraint satisfaction within a finite token budget (Dang et al., arXiv:2606.01926). Bias: LCD masks only immediately-violating tokens so renormalization deviates from the target conditional distribution (toy example: uniform p_lm over 3 bits with 'exactly one 1' gives LCD p=1/4,1/4,1/2 vs true 1/3 each). No finite-budget guarantee: a decoder can emit locally-valid unmatched '{' forever. Globally Constrained Decoding (GCD) masks with budget-aware criterion 𝒳_{t,n} guaranteeing validity at termination; P-GCD adds a distilled HMM. Measured (xLAM function calling, Llama-3.1-8B): constraint satisfaction at fixed budgets LCD 95.26–99.20% vs GCD/P-GCD 100.0%; accuracy LCD peaks 69.7% on xLAM JSON regardless of particles vs P-GCD 70.5–71.6%; P-GCD at k=4 (67.9%) beats LCD at k=8 (67.2%) on Spider. Cost: LCD 1.08x, GCD 1.10x unconstrained wall-clock, but P-GCD 3.11x–10.2x slower (5.26/8.23/17.30 ms/token at H=1024/4096/16384) plus one-time HMM distillation (~2 GPU-hours). Working on NFAs matters: Spider SQL char-level NFA 7,999 states vs DFA 57,263; DFA grows exponentially for JSON anyOf.

## F-011 `4cb71d0255cccf49`

Constraint Tax (Li et al., arXiv:2606.25605): when tool calling and JSON-Schema constraints are enabled together (schema compiled to grammar/FSM mask), all six tested open-weight models (Qwen3.6-35B, Qwen3.5-122B/397B, Qwen3-VL-235B, GPT-OSS-20B, Nemotron-3-Super) dropped Tool Invocation Rate from 100% to 0% (complete suppression), while closed GPT-5.4-mini stayed 100%. Robust across schema complexity, tool_choice='required', and frameworks (SGLang and vLLM identical). Root cause is mechanism-level: for Qwen XML-style tool format the leading '<' is not part of any valid JSON FSM state, so tool-call tokens are masked by design. Mitigation (Transparent Two-Pass Execution): TIR 0%→100%, JSON compliance unchanged, end-to-end success 0%→100%, at cost of one extra LLM round + tool-output context. Also cites Ray 2024: strict schemas raise format compliance but can lower answer accuracy.

## F-012 `6eb2a6b0a6c49c71`

Constrained decoding slightly helps reasoning task accuracy vs unconstrained (Llama-3.1-8B, Table 8): GSM8K 80.1% → 83.8% (Guidance), 83.7% (XGrammar); Last-Letters 50.7% → 54.0%; Shuffle-Objects 52.6% → 55.9%. But the TOON study (Matveev, arXiv:2603.03306; 21 models, up to 3 repair cycles) found plain JSON generation shows the best one-shot and final accuracy even vs constrained decoding, whose only significant advantage is lowest token usage. Mechanism: constrained decoding acts as a guardrail for weak models (Qwen2.5-Coder-7B-fast: 0% plain-JSON one-shot at 37,705 tokens → 75% under JSO at 4,440 tokens) but degrades strong models (Hermes-4-405B 92.5% plain → 35.0% constrained); JSO is the token-efficiency winner on simple tabular data. The measured quality effect of enforcement is small and capacity-directional.

## F-016 `473e91ddc0c06971`

CRANE (arXiv:2502.09061, ICML 2025) explains the format tax theoretically: constraining outputs to grammars that only allow syntactically valid final answers reduces reasoning expressivity (constant-layer LLM under such a grammar can only solve logspace-uniform TC0 problems; st-connectivity/NL-complete problems become unsolvable unless TC0=NL). Augmenting the output grammar with reasoning-permitting rules (Ga→R·G) preserves reasoning while keeping the final answer in the original grammar. CRANE decoding outperforms both constrained and unconstrained decoding: Qwen2.5-Math-7B 29% (constrained/CoT) → 38% CRANE; DeepSeek-R1-Distill-Llama-8B 21% → 31%; QwQ-32B 43% → 46%, with 100% parse where unconstrained CoT had ~10% syntax errors.

## F-017 `1d482a9b4839f28a`

In-Writing / 'Thinking Before Constraining' (arXiv:2601.07525): single-call two-phase — model reasons unconstrained (state −1), structured decoding engages only after a trigger token (state 0). Beats the NL-to-Format two-step baseline on almost every task: GSM8K LLaMA 74.7→77.9, DDXPlus Gemma 22.9→50.1 (+27.2 pp), MultiFin Gemma 70→86.9, Sports LLaMA 69.5→77.4. Overhead only 10–20 extra tokens (~0.5–1.5 s). Caveats: premature trigger-token generation is a documented failure (small models emit '{' mid-reasoning; mitigation: use '<eos>' as unique trigger), and it is 'not a perfect parser' (Appendix A.4.1 parse failures).

## F-018 `4626517e46b1c8e3`

Draft-Conditioned Constrained Decoding / DCCD (arXiv:2603.03305) formalizes constrained decoding as repeated reverse-KL projection onto the prefix-valid set; quality degradation is driven by low feasible mass — per-step distortion KL = log(1/α(h_t)); on a toy single-slot JSON the constraint admits ~1% of vocabulary. DCCD (unconstrained draft first, then constrained decoding conditioned on the draft) beats standard constrained decoding on every model×dataset: GSM8K 1B 15.24% → 39.04%, 1.5B 49.36→73.92 (largest gain), 7B 81.58→91.28, 14B 86.43→95.15; fixes GSM-Symbolic where CD collapses to 0.0 at 1B. A 1.5B+1.5B DCCD pair scores 12.7 accuracy-per-billion on MATH500 vs 3.6 for 8B CD (~253% better); 7B+1.5B beats a single 14B CD on GSM8K with 39% fewer parameters. Sampling+voting drafts scales better than sampling under hard constraints, saturating around n≈7.

## F-019 `a4951002397ee060`

'When Correct Isn't Usable' (arXiv:2605.02363) measured output accuracy = task-correctness × valid-JSON on strict {reasoning, answer} JSON contracts: NAIVE prompting reaches 77–85% task accuracy yet 0% output accuracy across all models/datasets; a minimal REFERENCE prompt still yields 0% for Gemma-2-9B and GPT-4o (both systematically wrap JSON in markdown fences). Constrained decoding (vLLM JSON grammar) enforces validity but at 3.6x–8.2x latency and can degrade task performance. Automated system-prompt optimization (AloLab black-box optimizer, meta-agent Claude Sonnet 4.5): GSM8K output accuracy 84.15/87.41/85.75%, MATH 34–40%, at 0.63–1.06x NAIVE latency; GPT-4o jumps 0% → 95.2% by adding a single 'no markdown fences' directive. Replacing the meta-agent with Claude 3 Haiku drops accuracy 84.15→61.0% (3/5 runs collapse) — optimizer capability, not the loop alone, drives reliability. Residual failure class is format-execution inconsistency (correct reasoning, wrong value in answer field) at 1.5–1.8% of failures.

## F-020 `97cf04e1f8130ba2`

The Constraint Tax on small models (Ray, arXiv:2605.26128; sub-3B SLMs, 15,000 generations): hard answer-only schema decoding raises schema validity 61.5%→100.0% but lowers answer accuracy 19.7%→11.0% (−8.7 pp) and raises wrong-valid-schema outputs 49.5%→88.9%. Per-model answer tax: Qwen2.5-0.5B −11.9 pp, Qwen2.5-1.5B −20.0 pp, SmolLM2-1.7B 0.0 (constraints help when they remove syntax failures without disrupting search). Production analogue: calendar tool-call task, prompt-only JSON 91.5% executable accuracy vs same object hard-encoded as schema 48.0% (−43.5 pp; 102/104 failures a single-field wrong duration_minutes — 'the error is semantic, not structural'); delayed-packaging control keeps 91.5% at 100% validity. Tax persists at 3B boundary (Qwen2.5-3B −15.3 pp). Backend-dependent: constrained decoding is a serving-path property, not model-only (SmolLM2 differs across vLLM/SGLang: 18.7 vs 25.7). Deployment rule: report schema validity, answer accuracy, executable accuracy, and wrong-valid-schema rate as a first-class reliability metric.

## F-021 `45e4bccf846fa0ba`

ATLAS-RTC (arXiv:2603.27905) is a closed-loop controller intercepting logits each step with a six-level graduated ladder (no-op → logit biasing → temperature modulation → token masking → mid-step KV-cache rollback), masking only at structural decision points and leaving value-generation zones free (intervening during value generation 'corrupts output'). On Qwen2.5-7B-Instruct: structured JSON under ambiguous prompts, first-attempt schema validity 56.7%→76.7% (+20.0 pp) with average latency falling 88% on the hard task (5,498→663 ms); agent tool-call first-attempt success 20.6%→58.3%, search tool 0.0%→96.7%. Rollback rare (~0.8 corrections/run, max depth 3 tokens). It enforces structure, not semantics: on send_email (missing required field) first-attempt success drops 16.7→0.0 pp; degrades on multiline string schemas and when baseline already saturates.

## F-022 `4d082f928948911f`

SE-wide structured-output taxonomy (arXiv:2606.09395): 9 models × 4 structured SE tasks, zero-shot. Unconstrained: syntax+structural errors account for ~80.7% of all failures on JSON and function-calling tasks (LLaMA-3.1-8B emits 1,833 syntax errors on BFCL v2; Gemma2-9b 2,203), while coding tasks have <20% format failures. Grammar/regex enforcement cuts syntax errors to near-zero but improves task-level accuracy only modestly (CallNavi exact-match 0.4883→0.5130; Spider pass@1 0.6767→0.7113; BFCL v2 AST-match 0.1759→0.5274). MoE models gain almost nothing from decoder-side constraints (Qwen3-30B-A3B exact-match unchanged; Mixtral-8x7B collapses to 0.2363 under LLGuidance, worse than unconstrained) — logit masking cannot redirect committed expert routing. Usable grammars are scarce: of top-10 TIOBE languages only Python (Lark) and SQL (Lark) parsed a basic control-flow test. TTMG (template token-match generation) nearly eliminates syntax errors yet substantial structural and semantic errors persist — syntax enforcement is necessary but insufficient.

## F-023 `f02881fc4dc7a2ea`

Autogrammar (arXiv:2608.05493) learns context-free grammars from documentation + execution logs for low-resource DSLs. Motivation: across 416 AWS services, 23% expose a string parameter requiring a DSL and AWS uses ≥59 unique DSLs. Measured precision on unseen data: 0.999 / 1.00 / 0.910 (CWIL/DQL/DSS) vs Arvada (SOTA oracle-based grammar induction) 0.025 on CWIL despite ~63k oracle calls / ~14.6 h, and vs direct-LM baselines (0.023–0.510) an order of magnitude below. Ablations: execution data is crucial, documentation largely dispensable; LTL constraints cut learning time 3.8x with no significant precision loss. End-to-end GCD loop improves LM success on 8/10 real CloudWatch tasks and matches a professionally-maintained grammar. The GCD grammar-availability constraint is removable — it becomes a data-availability problem, not a grammar-authoring problem.

## F-024 `edfc9ea838f66df0`

Schema key wording is an instruction channel under constrained decoding (Le, arXiv:2604.14862): holding model/prompt/structure/decoding engine (XGrammar) fixed and varying only where the instruction signal lives, Qwen2.5-7B GSM8K 79.61→86.50 under Key-only (+6.89), Qwen2.5-Coder-14B best under Both (+4.93); but Llama-3.2-3B drops 53.15→37.38 under Key-only (−15.77) while Prompt-only/Both improve it, and Llama-3.1-8B shows 0.00 Key-only change. Qwen models read the schema as a task instruction; LLaMA models treat schema wording as distraction. Interaction non-additive: on Qwen2.5-7B Math500 'Both' falls below baseline (25.20 vs 27.80). Identical JSON structure with different key names can move accuracy by ±15 pp depending on model family.

## F-025 `9266ab4c52fd8d11`

Token format of constrained output is a free reliability lever ('Lost in Space', arXiv:2502.14969; 1.28M GCD classifications, 4 families × 8 sizes, llama.cpp GBNF): real numbers in [0,1] perform best across all models (Spearman ρ 0.420–0.609) while integers/binaries are worst (integer ρ −0.160 for Llama 3.1 8b); leading-whitespace tokens improve performance 5–10% because LW and non-LW token twins are not exchangeable in embedding space (cosine 0.369–0.386 vs ~0.008–0.016 random) and LW tokens were 2.5–2.7x more prevalent in pre-training data; word-form outputs consistently worse than digits (ρ −0.12 to −0.41). Format sensitivity strongest for smaller models. A grammar admitting semantically-equivalent but differently-tokenized output can cost ~0.5 Spearman correlation.

## F-026 `9c53a0de2e7964bf`

'Are LLMs Ready for TOON?' (arXiv:2601.12014): the format-without-native-support cost is capacity-dependent. TOON cuts tokens −26.4% vs JSON, −49.4% vs XML, −15.3% vs YAML and estimated carbon −82.9%/−87.6%/−76.9%, but structural correctness collapses — GCS 0.513 vs JSON 0.840, YAML 0.872, XML 0.563 — because TOON is enforced only via prompts. Llama 3.3 70B shows no statistically significant difference (p>0.05 vs all formats), while Gemma 3 4B fails nearly completely (TOON GCS 0.045 vs JSON 0.779) and Qwen 3 4B drops 0.769→0.334. ## F-027 `162dbf907c0f473e`

Diffusion LLMs: structured-output collapse under stochastic sampling (Dang & Ermon, arXiv:2607.07026). Switching greedy→stochastic destroys unconstrained dLLM structured accuracy: Dream BFCL-Live (JSON) 63.9% → 22.3%; format gap is structural not semantic (Dream BFCL-Live JSON 63.9% → Python 22.4%). Exact constrained decoding over finite automata (chain graphical model, guaranteed 100% constraint satisfaction, log-depth tree sampler) recovers: BFCL-Live stochastic 22.3→69.0, Python 22.4→69.7, Sudoku 36.4→92.4, Countdown 53.6→100, at only +4% wall-clock (chain variant +114%). Ablation: recomputing remasking confidence under constrained marginals beats mean-field. Limitation: finite automata only, not CFGs.

## F-028 `0503a43026e3c7bc`

The multiplicative repetition penalty shipped across HuggingFace, vLLM, llama.cpp and a dozen engines corrupts schema compliance because its sign-branch reads a gauge-dependent quantity (the model's arbitrary logit zero-point) (Hollows, arXiv:2607.09791; abstract-level). At θ=1.3 it changes 58–96% of greedy tokens and drops the rate of valid schema-conformant output from 97% to 23% on 200 real JSON schemas (five ≤7B models). Fix: apply the penalty to normalized log-probabilities instead of raw logits (HuggingFace ships LogitNormalization, off by default). Structured-output compliance measurements must pin the full serving stack (sampler settings, zero-point gauge), not only the model/grammar.

## F-029 `c0b3c5493790ad8f`

## F-030 `a8eddf3f8aca8331`

OrderBench (arXiv:2607.18261) quantifies the schema-valid-but-wrong gap: GPT-OSS-120B-fast achieves 100% JSON and schema validity yet semantic success 83.0% (prompt) / 81.3% (JSON-schema); Qwen3-30B-A3B 100% schema-valid with semantic success only 30.7–31.3% and unsafe acceptance ~14–15%; Gemma-2-2B yields 100% schema-valid objects with 2.0% semantic success and 41.7% unsafe acceptance. ## F-031 `f7e3fa39e01a0051`

Aggregate field-level pass rate 4.6% (844/18,516 across 6 frontier models); best model (Gemini 3 Flash) 6.9%; valid-JSON rate 51% with valid-only field accuracy 72.9% (valid≠correct even when valid). 0% valid output on a 369-field SEC 10-K/Q schema across all models (0/2,583); excluding 10-K/Q pass rate is 28.0%. ## F-032 `a101c8e7ede3b6b3`

Grounding: word-level grounding F1 only specialized APIs return (best 46.4); every commercial VLM/coding agent scores 0.0.

## F-033 `a4d77e88c7e61873`

ScrapeGraphAI-100k (arXiv:2602.15189) — the largest real-world schema-constrained corpus: 93,695 production telemetry events, 18,000+ unique schemas. Average raw-corpus schema-validity ~93% but validation falls sharply at structural breakpoints: depth ≥7 drops validity 98%→20%; key count ≥200 drops to ~65%; composite complexity >1,000 drops to ~55%. Key count alone is a sufficient complexity proxy (metrics multicollinear, r≥0.98). 87.4% of requests came from GPT-4o-mini (behavior biased toward one model); validation measures only syntactic compliance, not semantic correctness. Distillation (Qwen3-1.7B, GPT-5-nano teacher): schema compliance 0.7954→0.9167 but value score stays 0.4624 vs 30B's 0.4797 — 'correctly identifying which fields to extract is easier than accurately extracting what those fields contain'.

## F-034 `22afd8a8bede9bbe`

Tam et al. 'Let Me Speak Freely?' (arXiv:2408.02442) — origin of the format-tax finding: format restrictions degrade LLM reasoning while stricter constraints degrade more. Headline drops (exact-match): GSM8K Claude-3-Haiku 86.5→23.4 under JSON (−63 pts); GPT-3.5-Turbo 75.99→49.25; LLaMA-3-8B 75.13→48.90. Degradation is not parsing failures (Last-Letter JSON parsing error rate 0.148% yet 38.15-point performance gap). ## F-035 `308c11e281ffbca4`

Two format-tax studies. (1) 'The Format Tax' (arXiv:2604.03616): 6 open-weight + 4 API models, structured output degrades every open-weight model (avg −5.8 to −8.7 pp); of 39 cells with significant effects, 36 (92%) are degraded by the format-requesting prompt alone, only 15 (38%) involve constrained decoding, 3 are GCD-only. GCD lifts format compliance 55.7%→92.2% with accuracy unchanged — the dominant cost enters at the prompt, not sampling bias. 2-Turn freeform-then-reformat recovers most loss (+6.8 pp avg, only 2/72 worsened ≈3% risk) at ~2x cost; thinking recovers more (+9.2 pp) but riskier (15% worsened). Newer closed models show near-zero tax. (2) 'Capacity, Not Format' (arXiv:2606.09410): with information-matched prose controls and 0% parse failures, JSON constraints are capacity-dependent — Sonnet absorbs them (p=0.25) but Haiku −36.2 pp and GPT-4o-mini −28.0 pp. Format-specific component −28.2 pp (Haiku), −19.3 pp (GPT-4o-mini); prompt-length component only −0.3 to −8.0 pp — the harm is premature serialization, not instruction length. Production-mode (GPT-4o-mini, MATH-Hard): CoT 60% → API JSON mode 51% → instruction-heavy JSON 34% → forced function calling 10% (−50 pp, models emit only tool-call arguments with no reasoning surface). Frontier immunity qualified: Opus 4.7 on AIME drops 96.2%→91.0%. Think-first-format-later recovers 79.5%/86.9% of the gap. Consensus: schema enforcement (decoding) is roughly cost-neutral on quality, but the format request itself is a real, capacity-dependent reasoning tax; forced-tool-calling is a production hazard on hard reasoning.

## F-036 `ec766cdefb66d42e`

## F-039 `8eb9a877c6a47673`

IFHierBench (arXiv:2607.27912) — nested output constraints: 600 prompts, constraint-tree depths d=0..3, deterministic checkers. 67.8% of format-bearing prompts in real apps (from 1,232 GitHub prompts) carry ≥1 nested scope — nested structured output is the norm. Even the strongest model only marginally exceeds 50% prompt-level accuracy (GPT-5.5 53.7%; Claude 42.8%; others 14.7–33.2%); every model loses 37–53 absolute points from d=0 to d=1 (the 'universal cliff at the very first level of nesting'); at d=3 only the two strongest retain >20%. ## F-040 `a3d101849aff988d`

Instruction Stacking Collapse (arXiv:2608.02639): follow rate falls from ~96% at one instruction to 0.60 (Sonnet), 0.43 (Gemini), 0.20 (GPT-5-mini) at twenty — sigmoid, non-linear; 'a single output JSON constraint is jointly unsatisfiable with nine others' — of 231 instruction pairs, 15 are logical impossibilities, and ~12% of satisfiable pairs fail far more than their parts predict (the JSON × title-length pair is −1.00); failure is structured interference, reproducible across models, not uniform forgetting. A training-free instruction compiler gives capability-graded recovery: +11.0 pp (GPT-5-mini), +3.3 pp (Gemini), −1.2 pp (Sonnet). Stacking a JSON-output requirement with other constraints is harmful even at the prompt level.

## F-041 `2512869e54f72f96`

Conformal risk control can't certify structured-output correctness beyond the base error rate (arXiv:2606.29054): models report 74–97% average confidence while actual risk ranges 3% (JSON) to 80% (NQ Open); whenever base risk μ > target risk α, any distribution-free certifier must abstain on ≥ (μ−α)/(1−α) of examples (CoNLL NER 72B forces ≥16% abstention at α=0.10; 3B ≥36%; NQ Open ~78% — hard NER/QA/CLS are uncertifiable at α=0.10). The path to certification is reducing μ (model scale), not tighter bounds. JSON extraction is the easy case: μ≈0, certifies at all scales with zero abstention. Bound hierarchy: Hoeffding 8.7% < Bernstein 11.9% < betting e-CRC 12.2% certified of 656. Under distribution shift static guarantees fail (60–71% violation rates); ACI restores control in the feasible regime (to 4–21%). Honest rule: compute μ first, then choose the bound and score (Self-Consistency strongest, AUROC to 0.82; Token Margin best for JSON, 0.82).

## F-042 `4f5ffa664297decb`

## F-043 `1d39a325632460a2`

TSCG (arXiv:2605.04107): JSON-schema volume causes a capability cliff for small models (4B–14B) — tool-calling accuracy collapses to 0–49% at >15 tools. A deterministic JSON→text schema compiler restores small models: Phi-4 14B 0% → 84.4% at 20 tools (90.3% at 50), Mistral 7B 35→80.1, Gemma 3 4B 49.9→67. The mechanism is format translation, not compression: R² of the accuracy predictor drops 0.88 → 0.03 when a plain-text baseline replaces JSON — almost the entire gain comes from writing the schema as text rather than JSON. On frontier models text also beats native function-calling API (mean +10.9 pp) while saving 6–50% tokens. Caveats: per-version operator inversion and super-additive negative operator interactions — no universal profile; aggressive compression harms strongly fine-tuned models. JSON (the universal production standard) is measurably the worst representation for small models.

## F-044 `39c9cdfc179c58ba`

State compression in two-agent relays (arXiv:2607.18265): schema-constrained JSON extraction achieves the highest feasibility accuracy 0.96 [0.90,1.00] and eliminates false-NONE (0/50), outperforming the uncompressed control (0.88, 3 false-NONE); a 250-word narrative summary collapses feasibility to 0.48 [0.34,0.62] with 8/50 false-NONEs despite the smallest payload (semantic goal-alignment 0.676 does not preserve numeric/categorical facts); embedding-based pruning matches control. ## F-045 `7263566e1ca0c610`

'Faithful, Not Corrective' (arXiv:2607.09678) — multi-hop relay format effects are tier-dependent: at the strong tier no telephone-game collapse occurs (every format retains QA recall ≥0.973 after 6 hops; loss concentrates in the first encoding step, free NL shows only a small drift slope −0.295); under a weak relay, across-format dispersion of hop-6 recall grows 8.7x, with an encoding toll paid by rigid formats (hop-1 Kv 0.765/Json 0.800 vs Constr 0.962) versus drift resistance of the fixed-key JSON schema (Json loses only 4.7 points over hops 1–6, retaining 0.94 of its hop-1-correct facts vs 0.74–0.85 for others). ## F-050 `7724947e09734d4a`

## F-051 `90b87f746aa7223d`

ToolBench-X (arXiv:2606.25819) benchmarks task completion under recoverable tool-environment hazards (five injected types: Specification Drift, Invocation Error, Execution Failure, Output Drift, Cross-source Conflict; each instance solvable via a valid recovery path). Findings (abstract-level): agents that perform well with reliable tools often fail under recoverable hazards; failures are driven less by tool-use volume or inference budget than by limited hazard diagnosis and ineffective recovery; targeted recovery hints recover many failed tasks while test-time scaling yields more limited gains — recovery quality, not retry quantity, is the binding constraint when the tool environment misbehaves.

## F-052 `b4ac4344ace6c5a2`

'Refining Over Resampling' (arXiv:2608.05643): sampling diversity saturates — on AIME-24 unique semantic reasoning clusters grow only from 1.2 (N=2) to 2.5 (N=32), so additional rollouts repeat dominant patterns. Breadth–depth refinement (N=8 rollouts, D=4 rounds of generator→self-critique→self-correction, then majority vote; verifier-free) consistently beats greedy, Maj@N, verifier-based best-of-N, beam search, and lookahead: Qwen2.5-1.5B MATH500 29.6 (RM@8) → 58.0%; average accuracy 13.21→25.67 (η=17.1 compute-normalized gain over Maj@8). ## F-055 `dc2abae1015a10fc`

Test-time-compute economics of retries: (1) Self-Consistency (arXiv:2203.11171) — sampling N paths + majority vote beats sample-and-rank, beam search, and prompt-ensembles at the same sample count, and answer consistency correlates with accuracy (a cheap know-when-it-doesn't-know signal usable to stop or escalate a retry loop). (2) Scaling LLM Test-Time Compute (arXiv:2408.03314) — compute-optimal difficulty-binned allocation 'can nearly outperform best-of-N using up to 4x less test-time compute (16 vs 64 generations)'; verifier search over-optimizes on easy questions (beam search degrades as budget grows), best-of-N better at high budgets/easy questions, search better at low budgets/hard; model-predicted difficulty nearly matches oracle. Uniform retries are up to 4x more expensive than difficulty-adaptive budgets.

## F-056 `cec104f546b03f85`

ContinuityBench (arXiv:2607.15899) — retry backoff at the infrastructure layer: with history-forwarding failover, context preserved in 99.20% (95% Wilson CI 98.27–99.63%) of 750 failover events vs near-0% for stateless failover. Two failure modes at C=100 concurrency: a race condition where parallel failovers corrupt shared proxy state, and a retry-storm (thundering-herd) where naive fixed-interval retries against a rate-limited fallback self-sustain and 'permanently lock out the fallback endpoint'; exponential backoff with jitter is 'necessary and sufficient' to resolve it. (Single-team system study, not independently replicated.)

## F-057 `b023dfa34d7b6603`

Dollar/token cost of retries — four independent measurements: (1) Token Budgets (arXiv:2606.04056) catalogs 63 confirmed production budget-overrun incidents across 21 frameworks (2023–2026), noting a single retry loop can spend thousands of dollars before an operator notices; central failure mode is delegation-fanout race. (2) Runtime-Structured Task Decomposition (arXiv:2605.15425): rerunning only the failed subtask cut retry cost to 436±132 tokens vs 1,632±145 static decomposition / 904±17 monolithic — up to 51.7% lower than monolithic, 73.2% lower than static. (3) Communication-Theoretic framework (arXiv:2605.09121): a cost-aware router achieves ~56% lower normalized cost than the strongest fixed technique at matched quality; contractivity shows generator-critic refinement turns contractive→divergent between 3B and 14B. (4) Agentic energy accounting (arXiv:2605.22883): agentic workflows consume 4.33x mean energy per successful goal vs linear baselines (888.1 J vs 205.3 J), driven by orchestration/retry structure, not inference compute. A 'retry loop' can be a $thousands incident or a ~50% cost reduction depending on where you retry and whether you aggregate.

## F-058 `cee7417852b29375`

Retry consistency (STED, arXiv:2512.23712): Claude-3.7-Sonnet shows near-perfect structural consistency 0.999±0.037 even at T=0.9 with only 19% degradation from T=0.1→0.9; Claude-3.5-Haiku is the most temperature-fragile (46% decline). ## F-059 `4c4453fd5125f78d`

JSON Whisperer (arXiv:2510.04717) — patch-based JSON repair instead of regeneration: LLM emits an RFC 6902 JSON Patch. Two measured failure modes of naive patch generation: missing related updates (fragmented patch generation causes models to miss necessary updates) and array index arithmetic ('even state-of-the-art models frequently miscalculate these shifts or conflate zero-based and one-based indexing'). Fix EASE (Explicitly Addressed Sequence Encoding) replaces positional arrays with dictionaries of stable keys plus a list_display_order string. Measured: patch generation with EASE matches full-regeneration quality within 5% while cutting tokens 31% (output 42% smaller), 42.3% lower latency, 42.5% lower cost. Few-shot (synthetic examples) is what makes patch generation work at all. Structured edits have their own failure modes distinct from structured generation.
