## F-000 `551c6fb883620cdf`

AWS CloudTrail records every request's principal in userIdentity.type with an explicit enumeration: Root, IAMUser, AssumedRole, Role, FederatedUser, Directory, AWSAccount, AWSService, IdentityCenterUser, Unknown; federation paths add SAMLUser / WebIdentityUser; userName, principalId, arn, and accessKeyId sit under the same element.

## F-001 `276b963419de5d5e`

AWS defines AWSService as 'The request was made by an AWS account that belongs to an AWS service' (e.g. Elastic Beanstalk assuming a role to call other services) — a dedicated kind for automated processes, distinct from human identity kinds.

## F-002 `adbc0cde1ae47dc7`

Google Cloud splits audit logs into four named classes: Admin Activity (user-driven API calls or actions modifying resource configuration/metadata), Data Access, System Event (log entries written by Google Cloud systems that modify resource configuration and aren't driven by direct user action, e.g. autoscaling adding/removing VMs), and Policy Denied — a first-order channel filter encoding whether a human drove an entry.

## F-003 `3aee4552498f51e4`

GCP audit logs carry the caller identity in AuditLog.authenticationInfo (principalEmail) and network origin in RequestMetadata.callerIp; for service-to-service calls inside Google's production network callerIp is redacted to 'private', and this includes calls made by Google-owned service accounts (service agents) even when initiated by a user.

## F-004 `832663c967f96aa0`

Kubernetes audit events (audit.k8s.io/v1 Event) record user ('Authenticated user information'), verb, sourceIPs, requestURI, requestReceivedTimestamp, responseStatus, userAgent, and annotations.

## F-005 `87e145dc13717659`

Kubernetes distinguishes principals by a username convention; audit policy rules match on users and userGroups; documented examples include username system:kube-proxy, group system:authenticated, and impersonation example system:serviceaccount:default:my-controller.

## F-006 `b85e02376e6436d9`

Kubernetes treats userAgent as explicitly untrusted: 'the UserAgent is provided by the client, and must not be trusted.'

## F-007 `e4d1d79629285352`

AWS sessionContext.sourceIdentity identifies the original user identity making the request across role assumption and role chaining (the field survives AssumeRole → service API calls); sessionContext.sessionIssuer records how temporary credentials were obtained; onBehalfOf carries the IAM Identity Center user a call was made for.

## F-008 `1696dd59343bd054`

Kubernetes impersonation records both identities in the audit event: the authenticated caller in user and the impersonated identity in impersonatedUser, e.g. user system:serviceaccount:default:my-controller with impersonatedUser jane.doe@example.com; an audit event is logged for each impersonation request.

## F-009 `00aadbc4be76ab80`

GCP attributes a human's actions executed through Google-managed service agents with the originating sign-in context, and notes that in multi-service flows, unless explicit identity delegation is in place, the service might propagate the immediate caller's origin.

## F-010 `79da1f19e3565dad`

GitHub's audit log records hashed_token (SHA-256 hash of the token used for authentication), programmatic_access_type, and token_scopes; covered authentication methods are personal access token, OAuth token, GitHub Apps (as an app installation or on behalf of a user), deploy key, and SSH key — any event attributable to a compromised token can be found by its hash.

## F-011 `97588acadbb60f33`

AWS records accessKeyId (the specific credential that signed the request) and credentialId for bearer-token callers.

## F-012 `f0389e3a1b973eae`

The OpenAI Agents SDK traces every run as a trace (workflow_name, trace_id, optional group_id to link multiple traces from the same conversation, metadata) composed of spans linked by trace_id/parent_id; agent runs are wrapped in agent_span(), handoffs in handoff_span(), tool calls in function_span(), LLM calls in generation_span(), guardrails in guardrail_span().

## F-013 `4ac0d73a111f7e22`

In a multi-agent framework the attribution unit is which agent performed which step in which workflow, on behalf of which conversation (group_id); linking the human/end-user at the trace level rather than the span level is a synthesis/opinion, not SDK-stated.
