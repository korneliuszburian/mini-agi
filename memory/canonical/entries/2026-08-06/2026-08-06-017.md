## F-000 `b5e9e0c951b1e6e6`

The MCP 'Skills Over MCP' working group is standardizing skills discovery/consumption; current direction is SEP-2640, a Resources-based Extensions-Track skill primitive, coordinated with the agentskills.io spec.

## F-001 `0f170eb63104f9a4`

OpenAI Agents SDK hooks: `RunHooks`/`AgentHooks` receive `on_tool_start`/`on_tool_end` (immediately before/after a local tool is invoked) plus `on_agent_start/end`, `on_handoff`, `on_llm_start/end`, attached per-run or per-agent; the `@tool` wrapper adds the runtime pipeline (schema validation, context injection, guardrails, timeouts, failure handling, tracing) around the raw callable, and calling `__wrapped__` bypasses it.

## F-002 `8eff920971cc7319`

Claude Code hooks fire per session (`SessionStart`/`SessionEnd`), per turn (`UserPromptSubmit`, `Stop`), and on every tool call (`PreToolUse`, `PostToolUse`, `PostToolUseFailure`, plus `PermissionRequest`/`PermissionDenied`); handlers can be shell commands, HTTP endpoints, MCP tools, LLM prompts, or subagents; `matcher` (tool name/regex) + `if` (permission-rule syntax) filter them; MCP tools match as `mcp__<server>__<tool>`; hooks can return `permissionDecision: 'deny'` to block a call; hooks live in settings files, managed policy, plugin `hooks/hooks.json`, or skill/agent frontmatter; `allowManagedHooksOnly` lets enterprises suppress user/project/plugin hooks.

## F-003 `579985981421cecf`

MCP change notification: servers declaring `listChanged` push `notifications/tools/list_changed` over a `subscriptions/listen` stream when the tool list changes — the protocol-level equivalent of a change hook.

## F-004 `2207c9782986060d`

LangChain tool execution is wrapped by middleware (e.g. `wrap_tool_call` for retry/error-to-message conversion); `ToolNode` runs tools inside the graph.

## F-005 `709bb8e0cf1de244`

CrewAI tools emit structured events (`ToolFailureDetectedEvent`, `ToolUsageFinishedEvent`) observed by subscribers via an event bus.

## F-006 `a7ce42ab7d93d083`

OpenAI Agents SDK guardrails have three layers: input (on first-agent input, parallel or blocking), output (on final output), and tool guardrails (input checks before a function-tool runs — can skip, replace output, or raise a tripwire; output checks after); tripwires raise exceptions and halt the run; ordering vs approvals is configurable via `ToolExecutionConfig(pre_approval_tool_input_guardrails=True)`; tool guardrails apply only to `function_tool` tools, not hosted/built-in tools or handoffs.

## F-007 `79491f200bb1b2ce`

OpenAI `allowed_callers` lets a tool declare whether it may be invoked directly by the model and/or by programmatic tool-calling (`["direct"]`, `["programmatic"]`, or both) — an access gate on the tool itself; approval/HITL interrupts run through `RunState` pause/resume.

## F-008 `e232f1c2ce57f2cf`

MCP enforced contract: `inputSchema` MUST be a valid JSON Schema object (2020-12 default); `outputSchema` is optional but binding when present (servers MUST provide conforming structured results, clients SHOULD validate); tool annotations from non-trusted servers MUST be considered untrusted; servers MUST validate all inputs, enforce access controls, rate-limit, and sanitize outputs; clients SHOULD validate tool results before handing them to the LLM; there SHOULD be a human able to deny invocations; SEP-1303 routes input-validation failures into the `isError: true` tool-result channel.

## F-009 `fe22d29d30fbcaf7`

Anthropic enterprise skills gates: pre-deployment approval gates for five dimensions (triggering accuracy, isolation, coexistence, instruction following, output quality); required eval suites of 3–5 queries per skill (should-trigger/should-not-trigger/ambiguous); separation of duties (authors ≠ reviewers); risk-tier vetting (code execution, instruction manipulation, MCP references, network calls, hardcoded credentials); integrity checksums verified at deploy time and signed commits; recall capped at max 8 skills per request to protect trigger accuracy.

## F-010 `a2ba28d2061e0152`

Claude Code treats hooks as not the enforcement layer: 'Because the `if` filter is best-effort, use the permission system rather than a hook to enforce a hard allow or deny', and a hook 'can deny the call, but staying silent doesn't approve it.'

## F-011 `c25768dab2411013`

LangChain schema contract is enforced by construction (type hints required, reserved names rejected); error handling is middleware-based with no built-in guardrail/tripwire layer in the tools docs; gating (HITL, interrupts) is a LangGraph graph-level feature, not a tool-level one.

## F-012 `d3efc6d2b15b11ba`

CrewAI: a tool returns `ToolFailure(code, retryable)` instead of a string — the framework records it and 'never guesses whether a string looks like an error'; `tool_failure_policy` (`ignore`/`warn` default/`raise`) with most-specific-wins precedence (tool → task → agent → crew); `max_usage_count` limits a tool's calls.

## F-013 `96875179b47df8ba`

Anthropic is the only framework with explicit 'drift' usage found: its enterprise Monitor stage says 'Rerun evaluations periodically to detect drift or regressions' and treats declining trigger accuracy or output quality as a signal to update or deprecate a skill — a manual/review-driven process, not an automated gate.

## F-014 `a5be82962e50e626`

## F-015 `886f02d1ed76d192`

MCP's nearest protocol-level drift signal is `notifications/tools/list_changed` — contract-change detection (a host detects its cached contract is stale), not behavioral drift.

## F-016 `0b8e26b881b8812b`

OpenAI (SDK + platform): no behavioral-drift detection appears in any page reached; the only lifecycle primitive is the SDK's observability hooks, and the platform skills guide advises 'inspect … before using', not periodic re-validation.

## F-017 `027989abc31d7253`

## F-018 `ecd4a6522505f64f`

Synthesis opinion: only Anthropic treats skill/tool quality as a reviewable, versioned artifact with a lifecycle and re-evaluation cadence; MCP is the only framework that turns the tool contract (schema) itself into an on-the-wire, cacheable, change-notifiable object; other frameworks put enforcement in the host application rather than the artifact.
